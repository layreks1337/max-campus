### Что было починено по ходу проверки

Полезно знать, если похожее вылезет снова:

| Симптом | Причина |
|---|---|
| **Бот получал сообщения, но не отвечал** | Кнопка `open_app` требует привязки мини-приложения к боту; до неё MAX отклоняет **весь** запрос с `Field 'webApp' cannot be null`. Теперь отправка понижается: `open_app` → ссылка → текст (`send_with_app_button`) |
| Инструмент `get_my_requests` падал, когда у студента есть заявки | Чтение `r.document` — ленивая связь, в async-контексте это `MissingGreenlet`. Нужен `selectinload` |
| `reset_demo.sh` «отрабатывал», ничего не меняя | `docker exec` без флага `-i` не пробрасывает stdin, и SQL из heredoc уходил в никуда |
| Пункты на экране онбординга не появлялись | Анимация входа из `opacity: 0` не завершалась; на первом экране это недопустимо — анимации убраны |
| Под ответом ассистента было десять одинаковых кнопок | Инструмент добавлял кнопку на каждую заявку; ограничено тремя |
| Текст на светлых пилюлях невидим | Базовые стили лежали вне `@layer base`; незалоенное `button { color: inherit }` перебивало утилиту `.text-canvas` |
| Заголовки прижаты к верхней кромке | Класс `.safe-top` задаёт `padding-top` и перебивал `pt-6`; теперь базовый отступ внутри самого класса |
| Пустой экран чата | `height: 100%` на `html/body` вместе с `overflow-x: hidden` делал body отдельным скроллером и ломал `sticky` |
| Справка не формировалась | `multi_cell` в fpdf2 оставляет курсор у правого поля, следующий вызов получал нулевую ширину |
| Ассистент выдумывал хакатоны | Модель не вызывала инструмент; добавлен детерминированный предзапрос данных |
| Уведомления роняли воркер | Сетевые исключения httpx не наследуют `OSError` и пролетали мимо обработчика |
| «Собрание в 05:52» | Сид прибавлял смещение к текущему времени вместо явного часа |

### Текущий публичный адрес

Смотреть актуальный:

```bash
docker compose logs tunnel | grep -oE "https://[a-z0-9-]+\.trycloudflare\.com" | head -1
```

⚠️ **Адрес меняется при каждом перезапуске туннеля.** После смены нужно:

```bash
# 1. прописать новый адрес
sed -i "s|^MINIAPP_PUBLIC_URL=.*|MINIAPP_PUBLIC_URL=<новый>|" .env
docker compose up -d --force-recreate app

# 2. переподписать вебхук бота
python scripts/setup_bot.py subscribe <новый>/webhook/max

# 3. отправить ссылку организаторам через форму сбора ссылок
```

## Что осталось сделать до сдачи

### Обязательное

1. **Стабильный хостинг вместо временного туннеля. ← ЖДЁМ РЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ**
   По п. 11 FAQ решение должно оставаться доступным весь период проверки.
   Quick-туннель живёт, пока работает эта машина, и меняет адрес при перезапуске.
   Обсудили два пути, пользователь пришлёт доступы позже:
   - **VPS** (предпочтительно) — нужны IP, пользователь, SSH-ключ или пароль.
     Развёртывание готовым `docker compose`, ~20 минут вместе с проверкой.
     У команды есть Yandex Cloud, но выданный ключ только для AI-сервисов —
     для создания ВМ нужны отдельные права.
   - **ngrok со статическим доменом** (бесплатно, если VPS не будет) — нужен
     только токен аккаунта. Чинит смену адреса, но сохраняет зависимость
     от того, что эта машина включена.
2. **Отправить ссылку организаторам** через форму сбора ссылок —
   привязку мини-приложения к боту выполняют они.
   Отправлять **только финальный** адрес, иначе ссылка протухнет.
3. **Проверить кнопку «Открыть приложение» после привязки.** Пока привязки нет,
   бот отправляет вместо неё обычную ссылку — приложение открывается в браузере.
   После привязки перезапустить приложение (флаг сбрасывается при старте)
   и убедиться, что кнопка появилась.
4. **Заменить адрес-заглушку в `DATA-API.yaml`** на финальный.
5. **Проверить приложение на реальном телефоне внутри MAX** — вебвью ведёт себя
   иначе, чем десктопный браузер. Возможно только после п. 2.

### Желательное

6. Презентация и видеозапись демонстрации (страховка от сбоя сети на защите).
7. Заменить смоделированные регламенты реальными документами вуза, если получим.
8. Обложки для событий и конкурсов без картинки — сейчас они рендерятся
   текстовой карточкой, это нормально, но с фото выглядит лучше.

## Известные ограничения

- **Кнопка `open_app`** не работает до привязки приложения к боту организаторами.
- **Уведомления тестовым пользователям** (id 900000–900999) не отправляются
  намеренно: таких аккаунтов в MAX нет, они бы забили очередь ретраями.
- **Quick-туннель** не гарантирует стабильный адрес.
- **Стриминг ответа ассистента** не включён: провайдер его поддерживает,
  но интерфейс ждёт ответ целиком. Заметно на длинных ответах.
- **Модерация публикаций** реализована на бэкенде, отдельного экрана для
  модератора нет — решения принимаются через API.
