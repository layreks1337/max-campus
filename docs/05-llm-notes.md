## ⚠️ Проблема №1 (среда, не API): кириллица в bash ломает запросы

**Это съело больше всего времени и выглядело как неисправность модели.**

Если передавать русский текст inline в `curl -d "..."` из bash на этой машине,
текст доходит до API повреждённым. Симптомы обманчивы — модель отвечает:

- «Пожалуйста, уточните ваш запрос. Что нужно сделать с этим текстом?»
- «Ваш запрос выглядит как задача на логику или математику…»
- «текст написан с использованием символов, которые мне не удаётся распознать» ← прямая улика

Из-за этого RAG-тест выглядел полностью провалившимся, хотя модель исправна.

**Решение:** payload писать в файл в UTF-8 и передавать через `--data-binary @file`.

```bash
curl -s -X POST "$YC_OPENAI_BASE/chat/completions" \
  -H "Authorization: Api-Key $YC_API_KEY" \
  -H "OpenAI-Project: $YC_FOLDER_ID" \
  -H "Content-Type: application/json; charset=utf-8" \
  --data-binary @tmp/payload.json
```

Для боевого кода проблемы нет — Python `httpx`/`openai` кодируют сами.
Это ограничение **только ручной отладки из bash**. Все временные payload-файлы — в `tmp/` (gitignored).

## ⚠️ Проблема №2 (поведение модели): не доводит цепочку инструментов до конца

Составной вопрос «**сколько дней** делается справка **и готова ли моя**» требует двух
инструментов: `search_regulations` + `get_my_requests`.

Что произошло:
1. Первый запрос → модель вызвала **только** `get_my_requests` (не оба, параллельных вызовов нет)
2. Вернули результат → модель ответила про статус заявки и **не стала** звать `search_regulations`

Вторая часть вопроса (про сроки) просто потерялась.

*Оговорка: наблюдение на одном примере, не статистика. Но полагаться на самостоятельную
цепочку инструментов нельзя.*

### Следствие — решение 019: RAG принудительный, а не по выбору модели

`search_regulations` **убираем из списка инструментов** и выполняем безусловно на каждый вопрос,
подмешивая найденные фрагменты в системное сообщение до вызова модели.

```
вопрос студента
   │
   ├─▶ эмбеддинг запроса (text-search-query) → гибридный поиск → топ-5 фрагментов
   │                                                    │
   │   ┌────────────────────────────────────────────────┘
   ▼   ▼
LLM: system = [роль + правила + профиль студента + НАЙДЕННЫЕ ФРАГМЕНТЫ]
     tools  = только личные данные и действия
             (get_my_requests, list_calendar_events, list_opportunities,
              get_my_matches, register_for_event, start_request, escalate_to_human)
```

Что это даёт:
- **Заземление гарантировано** — модель не может «забыть» посмотреть регламент и ответить по памяти
- На один round-trip меньше в самом частом сценарии
- Убирает главный риск продукта: выдуманный порядок начисления стипендии

Цена: один поиск на каждый вопрос, даже когда регламент не нужен. Копейки.

### Дополнительно в системный промпт

Раз цепочка ненадёжна — прописать явно:
> Если вопрос состоит из нескольких частей, вызывай инструменты по одному, пока не соберёшь
> данные по всем частям. Не отвечай, пока не покрыты все части вопроса.

И ограничить цикл: **максимум 4 итерации**, дальше отдавать что есть.

## ⚠️ Проблема №3: нет prompt caching

В ответе есть поле `usage.prompt_tokens_details.cached_tokens`, но оно стабильно `0`.

Следствия для кода:
- Не экономим на стабильном префиксе — системный промпт и описания тулов держать **компактными**
- Историю диалога резать агрессивно (последние N сообщений по бюджету токенов)
- Фрагменты RAG — только топ-5, не топ-20

## Поведенческие заметки

- Модель **требует внятного контекста задачи.** На короткие безличные вопросы вроде
  «Столица Франции?» отвечает «уточните запрос», хотя «Что такое HTTP?» и «2+2 сколько?»
  обрабатывает нормально. Вывод: всегда давать роль в `system` и формулировать вопрос
  как полноценный запрос, а не обрывок.
- `temperature: 0.1–0.3` для фактических ответов — на дефолте заметно больше отсебятины.
- Инструкция «ответь ровно фразой X, если данных нет» **соблюдается дословно** — на этом
  можно строить детект отказа в коде.
- `tool_call_id` имеет вид `000_<uuid>` — префикс с индексом. Возвращать как есть.
- Формат usage стандартный: `prompt_tokens`, `completion_tokens`, `total_tokens`.
