# Внедрение в вузе: новый вуз за день, пилот на институт, стоимость

> Код один на все вузы. Вуз задают `.env` и данные: шаблоны справок, регламенты,
> контингент. Ниже — что именно нужно сделать, как проверить пользу за четыре недели
> на одном институте и сколько стоит ассистент. Цифры стоимости — **оценка**,
> допущения перечислены рядом с ней.

---

## 1. Новый вуз за день

Что меняется, а что нет:

| Не меняется | Задаётся для вуза |
|---|---|
| Образ Docker, API, фронтенд, бот | `.env`: бот, адрес, название вуза, часовой пояс, ключ Yandex |
| Движок заявок, машина состояний, PDF, страница проверки | Виды справок — JSON-шаблоны |
| Ассистент: RAG, инструменты, защита от выдумок | Регламенты вуза — строки таблицы `kb_document` |
| Очередь сообщений, напоминания, «Люди», афиша | Контингент, коды привязки, сотрудники деканата |

### План на рабочий день

| # | Шаг | Где | Время |
|---|---|---|---|
| 1 | Сервер: VPS с Docker, открыты 80 и 443, домен или `<IP-через-дефисы>.sslip.io` | `git clone`, `cp .env.example .env` | 1 ч |
| 2 | Бот вуза в MAX: токен, имя, вебхук | `.env` + `python scripts/setup_bot.py subscribe https://<адрес>/webhook/max` | 30 мин |
| 3 | Вуз и режим: название, пояс, демо выключено | `.env`, см. ниже | 10 мин |
| 4 | Ключ Yandex AI Studio для ассистента | `.env`: `YC_API_KEY`, `YC_FOLDER_ID` | 15 мин |
| 5 | Первый старт с `SEED_DEMO_DATA=false`, затем контингент и коды привязки | таблицы `student`, `binding_code` | 1–2 ч |
| 6 | Сотрудники деканата: ФИО, подразделение, роль, код | список `STAFF` в `backend/app/seed/demo.py` | 15 мин |
| 7 | Виды справок: пройти девять шаблонов с деканатом — поля, сроки, что выдаётся сразу | `backend/app/seed/templates.py` | 2 ч |
| 8 | Регламенты вуза: положения о справках, стипендиях, общежитии, отпусках | таблица `kb_document` | 2 ч |
| 9 | Перезапуск, проверка сценария на своём аккаунте, ссылка организаторам MAX на привязку мини-приложения | `docker compose restart app` | 1 ч |

Итого около 8–9 часов работы одного человека плюс ожидание стороны MAX: привязку
мини-приложения к боту делает платформа, её срок от команды не зависит.

### Шаг 3. `.env` вуза

```bash
# Шапка PDF и часовой пояс вуза: расписание, приветствие, тихие часы, даты в чате
UNIVERSITY_NAME=Новосибирский государственный университет
UNIVERSITY_TZ_HOURS=7
MINIAPP_PUBLIC_URL=https://campus.example.ru
PUBLIC_HOST=campus.example.ru
MAX_BOT_TOKEN=...
MAX_BOT_USERNAME=...
# Случайная строка: python -c "import secrets; print(secrets.token_urlsafe(32))"
MAX_WEBHOOK_SECRET=...
# Без синтетики, без кнопки демо-входа, вход только с подписью MAX или по ссылке от бота
SEED_DEMO_DATA=false
DEMO_MODE=false
ALLOW_DEV_AUTH=false
```

Комментарии — отдельными строками, как в `.env.example`: не каждый разборщик `.env`
понимает `#` в конце строки, и комментарий может попасть в значение.

`SEED_DEMO_DATA=false` важен: иначе сид положит в пустые таблицы синтетику, а
настоящим студентам — учебные баллы и расписание из демо. С ним при старте
создаются только шаблоны заявок. Автовыдача тогда подписывается «Деканат
(автоматическая выдача)», а не «Демо-деканат».

### Шаг 5. Контингент

Выгрузка из деканата или учебной системы — CSV с колонками таблицы `student`:
ФИО, группа, институт, курс, номер зачётки, дата рождения, форма и основа обучения.

```bash
docker compose --profile vps up -d --build   # схема и шаблоны; с SEED_DEMO_DATA=false больше ничего
docker exec -i campus-db psql -U campus -d campus -c "\copy student(last_name, first_name, middle_name, group_name, faculty, course, record_book_no, birth_date, education_form, funding, enrolled_year) FROM pstdin WITH (FORMAT csv, HEADER true)" < students.csv
```

Файл — в UTF-8, первая строка — заголовки колонок.

Коды привязки — по одному на студента, раздаёт деканат (через старост или в
личном кабинете). Код одноразовый, подбор ограничен пятью попытками в час:

```sql
INSERT INTO binding_code (code, student_id, expires_at)
SELECT upper(substr(md5(random()::text), 1, 4) || '-' || substr(md5(random()::text), 1, 4)),
       s.id, now() + interval '1 year'
FROM student s
WHERE NOT EXISTS (SELECT 1 FROM binding_code b WHERE b.student_id = s.id)
ON CONFLICT (code) DO NOTHING;   -- совпадение кодов маловероятно; повторить, пока не вставится 0 строк
```

Интеграции с 1С, «Тандемом» и другими учебными системами нет — это разовая выгрузка.
Расписание и баллы без выгрузки не показываются: таблицы `schedule_slot` и
`grade_item` остаются пустыми, API отдаёт пустые списки — в пилоте это разделы
«на потом», главный сценарий от них не зависит.

### Шаг 7. Новый вид справки — словарь, не код

```python
{
    "key": "student_card_duplicate",
    "title": "Дубликат студенческого билета",
    "category": "Заявления",
    "sla_hours": 72,
    "doc_template": "decision",
    "produces_document": True,
    "schema_json": {"fields": [
        {"name": "reason", "type": "select", "label": "Причина",
         "options": ["Утерян", "Испорчен"], "required": True},
    ]},
    "route_json": [
        {"status": "IN_REVIEW", "actor_role": "STAFF_CLERK"},
        {"status": "SIGNING", "actor_role": "STAFF_HEAD"},
        {"status": "READY"},
    ],
}
```

Форму по этому описанию рисует фронтенд, данные проверяет бэкенд, маршрут
согласования ведёт машина состояний. Шаблоны обновляются при каждом старте.
`"auto_issue": True` — выдавать сразу, без очереди: имеет смысл только для типовых
справок и только если вуз принимает электронный документ (см. ограничения ниже).

### Шаг 8. Регламенты

```sql
INSERT INTO kb_document (title, source_type, source_url, body, is_demo, active, updated_at)
VALUES ('Положение о стипендиальном обеспечении', 'regulation',
        'https://<сайт вуза>/docs/…', '<текст документа>', false, true, now());
TRUNCATE kb_chunk;   -- после перезапуска база знаний переиндексируется сама
```

Затем `docker compose restart app`. Ассистент цитирует документы со ссылкой на
источник, поэтому `source_url` лучше заполнять. Проверка — 20–30 типовых вопросов
деканата в чате ассистента.

### Что остаётся за вузом

- **Юридическая сила документов.** PDF сейчас без электронной подписи. Для боевой
  выдачи нужна УКЭП вуза; место стыковки — генерация PDF
  (`modules/requests/pdf.py`) и страница проверки `/verify/{uuid}`.
- **Персональные данные.** Контингент — это ПДн: сервер в России, договор с
  хостингом, согласие студентов на обработку, приказ вуза о пилоте.
- **Форма учреждения** в шапке PDF — «Федеральное государственное бюджетное
  образовательное учреждение высшего образования», общая для государственных вузов.
  Для другой формы — константа `UNIVERSITY` в `pdf.py`.

## 2. Пилот: один институт, четыре недели

**Кто.** Один институт, например ИМИТ ИГУ: все курсы, основная группа —
первокурсники. Два-три сотрудника деканата работают с очередью в приложении.

**Что проверяем.** Три гипотезы, у каждой — одна метрика:

| Гипотеза | Метрика | Как считаем | Цель к 4-й неделе |
|---|---|---|---|
| Студенты заказывают справки в чате, а не в окне | **Доля справок через чат** | справки, выданные через «Кампус», ÷ все справки института за неделю (через «Кампус» + журнал деканата) | ≥ 50 % |
| Справка готовится быстрее | **Время выдачи** | медиана от подачи до выдачи по истории заявок, отдельно типовые и нетиповые | нетиповые — в пределах норматива (3 рабочих дня), типовые — в день подачи |
| Визитов в деканат становится меньше | **Визиты в деканат за справками** | число очных обращений за справками в неделю по журналу окна, против базовой линии | −30 % |

Дополнительно следим: доля привязавшихся студентов, число вопросов ассистенту и
доля обращений, переданных в деканат, оценка студентов и сотрудников в конце.

**Базовая линия.** До старта деканат поднимает журнал за четыре недели до пилота:
сколько справок выдано, за сколько дней, сколько было очных обращений. Без неё
метрики не с чем сравнить.

### По неделям

| Неделя | Что происходит | Что меряем |
|---|---|---|
| 0 (подготовка) | «Новый вуз за день» для института: контингент, коды, 2–3 сотрудника, регламенты; с деканатом решаем, какие справки выдавать автоматически | базовая линия по журналу |
| 1 | Запуск на первокурсниках: кураторский час, коды через старост, «закажите справку об обучении» | доля привязавшихся, первые справки, вопросы ассистенту без ответа → дополняем регламенты |
| 2 | Все курсы института; сотрудники ведут очередь в приложении, очный приём сохраняется | три метрики за неделю, время ответа сотрудника |
| 3 | Штатная работа; опрос студентов и сотрудников (5 вопросов) | три метрики, оценки |
| 4 | Итоги: сравнение с базовой линией, отчёт, решение о масштабировании на вуз | три метрики, стоимость YandexGPT по факту |

**Критерий успеха пилота** — две метрики из трёх достигли цели, а сотрудники
деканата не тратят на справку больше времени, чем в окне.

### Запросы для метрик

```sql
-- Справки через «Кампус» по неделям для института
SELECT date_trunc('week', d.issued_at) AS неделя, count(*) AS справок
FROM document d
JOIN request r ON r.id = d.request_id
JOIN student s ON s.id = r.student_id
WHERE s.faculty = 'Институт математики и информационных технологий'
GROUP BY 1 ORDER BY 1;

-- Медиана времени от подачи до выдачи, часы: автоматические и через сотрудника
SELECT d.issued_by LIKE '%автоматическая выдача%' AS автоматически,
       count(*) AS справок,
       percentile_cont(0.5) WITHIN GROUP (
         ORDER BY extract(epoch FROM d.issued_at - r.created_at) / 3600
       ) AS медиана_часов
FROM request r
JOIN document d ON d.request_id = r.id
GROUP BY 1;

-- Вопросы ассистенту и обращения, переданные в деканат
SELECT (SELECT count(*) FROM ai_message WHERE role = 'user') AS вопросов,
       (SELECT count(*) FROM request WHERE template_key = 'support_question') AS в_деканат;
```

Визиты в деканат система не видит — их считает деканат по журналу или талонам
электронной очереди, как и для базовой линии.

## 3. Сколько стоит ассистент: YandexGPT на 1000 студентов

> **Это оценка, а не счёт.** Токены замерены на стенде, цены — из публичных
> тарифов, число вопросов — допущение. Перед пилотом цены сверить со страницей
> тарифов Yandex AI Studio и включить в Yandex Cloud оповещение о бюджете.

### Что замерено

28.09.2026 на стенде: шесть типовых вопросов из `scripts/test_assistant.py`
(сроки справки, социальная стипендия, общежитие, «где моя заявка», «какие справки
можно заказать», хакатоны). Счётчик `usage` из ответа YandexGPT:

| | Среднее | Разброс |
|---|---|---|
| Вызовов модели на вопрос | 1 | 1 |
| Входные токены (промпт, регламенты, данные студента) | 1 966 | 1 552–2 506 |
| Выходные токены (ответ) | 62 | 24–101 |

Основная часть — вход: системный промпт, пять фрагментов регламентов и данные из
инструментов. Эмбеддинг вопроса — десятки токенов, на стоимость не влияет.

### Допущения

- **3 000 токенов на вопрос** — замер (~2 000) с запасом в полтора раза: в длинном
  диалоге растёт история, иногда нужен второй проход модели.
- **Цены синхронного режима**, ₽ за 1000 токенов, вход и выход по одной цене (с НДС,
  по сводкам публичного тарифа на август 2026): YandexGPT Pro 5.1 — 0,80;
  YandexGPT Pro 5 — 1,20; YandexGPT Lite — 0,20. В `.env` стоит `yandexgpt/latest`,
  какая за ним версия Pro — решает Yandex, поэтому считаем по обеим.
- **Скидку за кешированные токены не учитываем** — оценка сверху. Кеширование
  у YandexGPT непостоянно: в проверке 24.09 (`docs/05-llm-notes.md`) поле
  `cached_tokens` было 0, в замере для этой оценки — около половины входа.
  Опираться на скидку нельзя.
- **Сколько спрашивают** — три сценария ниже, это допущение до пилота.

### Оценка на 1000 студентов в месяц

Цена вопроса: Pro 5.1 — 2,40 ₽, Pro 5 — 3,60 ₽, Lite — 0,60 ₽.

| Сценарий | Кто спрашивает | Вопросов | Pro 5.1 | Pro 5 | Lite |
|---|---|---|---|---|---|
| Спокойный месяц | 30 % студентов по 5 вопросов | 1 500 | 3 600 ₽ | 5 400 ₽ | 900 ₽ |
| Базовый | 50 % по 10 вопросов | 5 000 | 12 000 ₽ | 18 000 ₽ | 3 000 ₽ |
| Пик: сентябрь первокурсников, сессия | 80 % по 20 вопросов | 16 000 | 38 400 ₽ | 57 600 ₽ | 9 600 ₽ |

В базовом сценарии это **12–18 ₽ на студента в месяц** на Pro. Эмбеддинги
(около 0,01 ₽ за 1000 токенов) добавляют порядка рубля в месяц, разовая индексация
сотни регламентов — единицы рублей. Голосовые вопросы (SpeechKit) и сервер в
оценку не входят.

### Как держать расходы

- Лимит уже есть: 20 вопросов за 10 минут на пользователя (`ASSISTANT_RATE_LIMIT`).
- Простые вопросы по регламенту — на Lite, она вчетверо дешевле Pro 5.1: в коде
  есть переключатель `cheap` у вызова модели, его нужно задействовать в маршрутизации.
- Оповещение о бюджете в Yandex Cloud: без денег на счёте модель не отвечает,
  ассистент отдаёт выдержки из регламентов, найденные только полнотекстовым поиском
  (векторная половина поиска без эмбеддингов выключается).
- В пилоте — фактический расход по неделям из биллинга, чтобы заменить эту оценку
  цифрой.
