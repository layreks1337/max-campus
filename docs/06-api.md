## Вход

Каждый запрос несёт подписанную строку запуска мини-приложения:

```
Authorization: MaxInitData <initData>        (или X-Init-Data: <initData>)
```

- **Подпись MAX.** `secret = HMAC_SHA256(key="WebAppData", msg=BOT_TOKEN)`, подписаны
  пары `key=value` из WebAppData, кроме `hash`, отсортированные по ключу и склеенные
  через перевод строки. Сравнение constant-time, срок жизни строки — час
  (`INIT_DATA_TTL_SECONDS`), в том числе для проверенной и закешированной на 5 минут.
- **Ссылка от бота** (решение 057). Пока мини-приложение не привязано к боту, кнопка
  в чате открывает браузер со ссылкой `?lt=<max_user_id>.<exp>.<sig>`, фронтенд
  передаёт токен заголовком `Authorization: MaxLink <токен>`.
  `sig = hex(HMAC_SHA256(key=LINK_SECRET или производный от токена бота, msg="<max_user_id>.<exp>"))`,
  срок — сутки. Бот выдаёт токен только собеседнику, поэтому id в нём — настоящий
  пользователь MAX.
- **Тестовый вход** для проверки вне мессенджера: вместо подписи — `dev:<id>:<Имя>`,
  например `Authorization: MaxInitData dev:900001:Anna`. Только для тестовых id
  900000–999999, остальные получают 401: настоящим пользователем MAX без подписи не
  представиться. Имя — латиницей (заголовки допускают только latin-1). Выключается
  переменной `ALLOW_DEV_AUTH=false`. Сообщения в MAX тестовым id не отправляются.

Логинов и паролей в сервисе нет. Готовые тестовые роли и как войти каждой —
[`testdata/roles.json`](../testdata/roles.json).

## Роли

| Роль | Кто | Что может |
|---|---|---|
| `STUDENT` | Аккаунт, привязанный к студенту — по коду или демо-копией | Только свои данные: заявки, справки, диалоги, отклики |
| `STAFF_CLERK` | Специалист деканата | Очередь заявок, приём в работу, уточнение, отклонение, передача на подпись. Выдавать документы не может (403) |
| `STAFF_HEAD` | Подписант | Всё, что специалист, плюс «Готова» и выдача документа. Аккаунт с демо-копией получает эту роль в один тап и видит только заявки своей копии |
| `ORGANIZER` | Организатор | Создание событий календаря (вне демо-стенда) |
| `MODERATOR` | Модератор | Модерация пользовательских публикаций (вне демо-стенда) |
| `ADMIN` | Администратор | Все действия сотрудников |

Принципы:

- Роль читается из справочника сотрудников, никогда из запроса клиента, и проверяется
  по действию (`core/deps.py`, решение 068).
- Студент не получит чужие заявки или отклики. Готовый PDF и страница проверки
  открываются без входа по ссылке с uuid4 документа — так работает QR-код; списка
  документов без авторизации нет.
- Инструменты ассистента исполняются от имени текущего пользователя; параметра «чей»
  в их схеме нет намеренно.
- Билет на входе проверяет любой сотрудник (все роли, кроме `STUDENT`): код подписан
  HMAC, без самого билета чужую запись не отметить.
- Демо-стенд (`DEMO_MODE=true`). Коды сотрудников опубликованы, поэтому события и
  модерация отвечают 403 `DEMO_READ_ONLY`, возможность от сотрудника уходит на
  модерацию, а в очереди сотрудника по коду нет заявок демо-копий. В «Людях» — только
  объявления синтетических студентов.

## Ошибки

Единый конверт: `{ "error": { "code": "...", "message": "...", "details": { } } }`.
В `openapi.json` это схема `ErrorResponse`: у каждого метода перечислены его отказы —
401 у методов со входом, 403 у методов сотрудника, 409 `BINDING_REQUIRED` там, где
нужен привязанный студент, 413 у методов с телом, 422 и остальные — по коду роута
(решение 080). Вход описан схемами безопасности `MaxAuth` (`Authorization`) и
`MaxInitDataHeader` (`X-Init-Data`).

| Код | HTTP | Когда |
|---|---|---|
| `NO_AUTH` | 401 | Нет заголовка авторизации |
| `BAD_INIT_DATA` | 401 | Подпись запуска или ссылки бота не сошлась, истекла, либо тестовый вход с нетестовым id. Фронтенд показывает «Сессия устарела» |
| `BINDING_REQUIRED` | 409 | Студенческий не привязан, нужен онбординг |
| `BAD_CODE` | 404 | Код привязки или сотрудника не найден или уже использован |
| `ALREADY_BOUND` | 409 | Студент по этому коду уже привязан к другому аккаунту |
| `CONFLICT` | 409 | Демо-профиль не создан из-за двойного нажатия — повторить запрос |
| `FORBIDDEN` | 403 | Недостаточно прав для операции (роль не та) |
| `DEMO_READ_ONLY` | 403 | На демо-стенде публикация для всех (события, модерация) закрыта |
| `NOT_FOUND` | 404 | Объект не найден или принадлежит другому пользователю |
| `GONE` | 410 | Файл документа больше недоступен на сервере |
| `VALIDATION_FAILED` | 422 | Ошибки формы или параметров. У формы заявки — сообщения по полям в `details`, у параметров запроса — `details.errors` (`loc`, `msg`, `type`) |
| `BAD_TRANSITION` | 409 | Недопустимый переход состояния заявки |
| `REGISTRATION_CLOSED` | 409 | Регистрация на событие закрыта |
| `CANCELLED` | 409 | Билет относится к отменённой записи на событие |
| `ATTENDED` | 409 | Проход по билету уже отмечен — запись на событие не отменить |
| `BAD_TICKET` | 400 | Код билета не распознан (в строке нет кода вида `T12-ABCDE`) или подпись неверна. Принимается сам код, ввод с пробелом и ссылка из QR с кодом |
| `BAD_FILE_TYPE` | 400 | Вложение не PDF и не изображение |
| `FILE_TOO_LARGE` | 400 | Вложение больше 10 МБ |
| `PAYLOAD_TOO_LARGE` | 413 | Тело запроса больше 1 МБ (у `/api/uploads` — 11 МБ); не дочитывается |
| `UPLOAD_QUOTA` | 429 | Исчерпана квота вложений студента |
| `STORAGE_FULL` | 507 | Хранилище вложений сервера заполнено |
| `RATE_LIMITED` | 429 | Превышен лимит: подбор кода привязки, неверные коды билетов, демо-вход с тестовых id, вопросы и голосовые вопросы ассистенту |
| `DEMO_DISABLED` | 404 | Демо-вход выключен на сервере (`DEMO_MODE=false`) |
| `DEMO_UNAVAILABLE` | 503 | Демо-данные ещё не загружены (первые секунды после старта) |
| `BAD_WEBHOOK_SECRET` | 403 | Вебхук с неверным `X-Max-Bot-Api-Secret` или без него, когда секрет обязателен: MAX уже присылал верный или включён `MAX_WEBHOOK_REQUIRE_SECRET` (решение 077) |
| `STT_FAILED` | 502 | SpeechKit не распознал голосовой вопрос или недоступен |
| `UNAVAILABLE` | 503 | Распознавание речи не настроено (нет ключа Yandex Cloud) |
| `TOO_SHORT` | 422 | Голосовая запись слишком короткая |
| `HTTP_ERROR` | — | Запасной код конверта для ошибки без собственного кода |
| `INTERNAL` | 500 | Необработанная ошибка сервера; подробности — только в логе |

## Лимиты

Все лимиты — в памяти процесса, рестарт их обнуляет. «С адреса» — по
`X-Forwarded-For` от Caddy; запросы изнутри сервера (смоук-тест) его не имеют.
Тестовые id браузерного входа придумываются без счёта, поэтому для них действуют ещё
и лимиты с адреса; скрипт со многих адресов их обходит.

| Что | Лимит | Почему |
|---|---|---|
| Размер запроса | 1 МБ, у `/api/uploads` — 11 МБ; сверх лимита тело не читается (413) | Иначе один большой запрос без авторизации съедал память сервера (1 ГБ) |
| Привязка студенческого | 5 попыток в час на аккаунт и 20 неудачных в час с одного адреса | Перебор кода со сменой тестовых id упирается в лимит с адреса |
| Проверка билетов на входе | 20 неверных подписей за 10 минут на сотрудника; нераспознанная строка не считается | Подпись билета — 5 символов, чтобы её можно было продиктовать, а коды сотрудников на стенде публичные (решение 071) |
| Демо-вход (копии студента) | Аккаунт MAX — без лимита, одна копия на аккаунт. Тестовые id — 120 новых копий в час на сервер и 10 с одного адреса | Общий лимит на всех позволял скрипту закрыть демо-вход экспертам из MAX (решение 067) |
| Вопросы ассистенту и голосовые вопросы | 20 за 10 минут на пользователя; для тестовых id — ещё 40 за 10 минут с адреса. Ответ — не дольше 25 секунд | Каждый вопрос — платный вызов YandexGPT или SpeechKit, адрес публичный |
| Вложения к заявкам | 20 файлов на студента, 500 МБ на сервер, 1 ГБ диска всегда свободен | Диск стенда — 10 ГБ, ночная копия хранит файлы семь раз |
| Исходящие сообщения в MAX | 20 запросов в секунду | Платформа допускает 30; держим запас |
