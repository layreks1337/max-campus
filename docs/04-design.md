## 1. Синтез: откуда что берём

Два референса противоположны по тону, и это хорошо — продукт естественно делится надвое.

| | **Mobbin** (белая галерея) | **Panora** (тёмный фид) |
|---|---|---|
| Тон | документ, печатная плоскость | витрина, фотография |
| Где применяем | **Заявки, формы, чат ассистента, деканат** | **Главная-лента, Люди (матчинг)** |
| Почему | бюрократия должна читаться, а не впечатлять | события и возможности продаются картинкой |

**Что общего — на этом и стоит система:**
- всё интерактивное — стадион-пилюля (`rounded-full`), прямоугольных кнопок не существует
- карточки 24px, медиа и поля 16px
- огромный дисплейный шрифт с плотным интерлиньяжем
- хром бесцветный, цвет приносит контент
- один акцент, применяется скупо

**Решение 023: тёмная тема — основная.** Мини-апка открывается внутри мессенджера с телефона,
чаще вечером и в тёмном клиенте. Светлая — полноценная, но вторичная.

text-muted      #A1A1A6   вторичный
text-faint      #6E6E73   третичный, плейсхолдеры

### Цвет — светлая тема

### Семантика статусов

Mobbin семантической палитры не имеет — но у нас заявки со статусами, без неё не обойтись.
Правило: **статус несёт текст и тинт-чип, цвет добавляется только на терминальных состояниях.**

| Состояние | Тёмная | Светлая | Где |
|---|---|---|---|
| Черновик / нейтрально | `text-faint` + `field` | то же | DRAFT |
| В работе | `accent` | `accent` | SUBMITTED · IN_REVIEW · SIGNING |
| Требует действия | `#E3A008` | `#B26A00` | NEEDS_INFO |
| Готово | `#35C07A` | `#1F9D55` | READY · ISSUED |
| Отклонено | `#FF6B5E` | `#C0392B` | REJECTED |

Не раскрашивать всю карточку — только точку-индикатор, чип и текст статуса.

### Типографика

Saans коммерческий — берём **Inter Variable**, как рекомендует сам гайд.
Маппинг весов: 652 → **650**, 456 → **450**, 300 → **300**.

Шкала Mobbin рассчитана на десктопный лендинг (display 80px). Для мини-апки на телефоне
пересчитал:

| Токен | Размер | Вес | Интерлиньяж | Где |
|---|---|---|---|---|
| `display` | 44px | 650 | 1.0 | Обложечные карточки (месяц, название хакатона) |
| `h1` | 32px | 650 | 1.05 | Заголовок экрана |
| `h2` | 24px | 650 | 1.13 | Секция |
| `h3` | 20px | 650 | 1.2 | Заголовок карточки |
| `title` | 17px | 600 | 1.3 | Строка списка, имя поля |
| `body-lg` | 18px | 300 | 1.38 | Лид-абзац, подзаголовок героя |
| `body` | 15px | 450 | 1.45 | Основной текст, сообщения чата |
| `body-sm` | 13px | 450 | 1.45 | Подписи, описания полей |
| `label` | 12px | 600 | 1.33 | Чипы, бейджи |
| `caption` | 12px | 450 | 1.33 | Метаданные, таймстемпы |

Правила: letter-spacing везде 0 · sentence case, без капса · заголовки-предложения
заканчиваются точкой · контраст веса (650 против 300) — главный инструмент иерархии.

### Радиусы и отступы

```
rounded: none 0 · sm 16px · md 24px · full 9999px
spacing: 4 · 8 · 12 · 16 · 24 · 32 · 48 ; секции 64px (не 80 — экран телефона)
```

### Высоты — где Mobbin приходится нарушить

Mobbin бестеневой. На чёрном фоне одни заливки не разделяют слои — плоскость слипается.
**Правило по темам:**

- **Светлая:** теней нет. Иерархия — тинты и хайрлайны. Строго по Mobbin.
- **Тёмная:** заливка + **внутренний верхний блик** + мягкая внешняя тень.

Приём взят из присланного `expanding-tabs` и совпадает с Panora:

```css
/* поднятая пилюля в тёмной теме */
box-shadow:
  0 7px 18px rgba(0,0,0,0.34),
  inset 0 1px 0 rgba(255,255,255,0.06),
  inset 0 2px 0 rgba(255,255,255,0.18);
```

## 3. Компоненты

### Нижняя навигация — плавающая пилюля

Присланный `expanding-tabs` и нижний бар Panora — **один и тот же паттерн**: неактивные
табы иконкой, активный раскрывается и показывает подпись. Берём его как есть.

```
        ┌──────────────────────────────────┐
        │ ⌂  📄  👥  ⌜💬 Чат⌝              │   ← активный раскрыт
        └──────────────────────────────────┘
              плавает над контентом, safe-area снизу
```

**Четыре таба, не пять** — пять пилюль не помещаются на 320px:

| Таб | Содержание |
|---|---|
| **Главная** | Лента: ближайшие события, рекомендованные возможности, статус активных заявок |
| **Заявки** | Подача, список, трекинг. Для сотрудника — очередь деканата |
| **Люди** | Матчинг: колода интентов, мои матчи, наставник |
| **Чат** | Ассистент |

Профиль — аватар в шапке, не таб.

### Карточка-обложка (язык Panora)

Для событий и возможностей. Фото на всю ширину, поверх — название `display` 44px,
чип-счётчик слева сверху, круглая кнопка «…» справа.

```
┌────────────────────────────────┐
│ ⟨ до 12 окт ⟩              (…) │
│                                │
│          [фотография]          │
│                                │
│   Цифровой прорыв.             │  ← display, белый, тень для читаемости
└────────────────────────────────┘
   24px радиус, без рамки
```

Текст поверх фото всегда под градиентной подложкой снизу — иначе на светлых снимках нечитаемо.
Нет обложки → сплошная `surface` и название в `h2`.

### Карточка-документ (язык Mobbin)

Для заявок. Никаких фото.

```
┌────────────────────────────────┐
│ ● На подписи        №2025-0417 │   ← точка статуса + моноширинный номер
│                                │
│ Справка об обучении            │   ← h3
│ Подана 22 сентября             │   ← caption, muted
│                                │
│ ▓▓▓▓▓▓▓▓▓░░░░  осталось ~1 день│   ← тонкий прогресс
└────────────────────────────────┘
   surface, hairline, 24px
```

### Степпер статуса

Вертикальный, на экране заявки. Пройденные — `ink`, текущий — `accent` с пульсацией,
будущие — `text-faint`. Слева тонкая линия `hairline`.

### Чат ассистента

- Сообщение студента — пилюля `surface-raised`, прижата вправо, максимум 80% ширины
- Ответ ассистента — **без пузыря**, просто текст на канвасе (так читается длинный ответ)
- Под ответом — блок источников: чипы `button-pill-soft` с названием регламента
- Пока думает — три пульсирующие точки, не спиннер
- Стриминг обязателен: текст появляется по мере генерации

### Колода свайпов

Карточка 24px, `surface`, стопка из трёх со смещением и уменьшением масштаба.
Внизу две круглые кнопки: ✕ (`surface-raised`) и ✓ (`accent`).
Поверх при драге — штампы «Откликнуться» / «Пропустить» на 30% смещения.

### Поля ввода

Заливка `field`, **рамки в покое нет**, радиус 16px, паддинг 12/16.
Фокус — кольцо 2px `ink` (светлая) / `accent` (тёмная). Высота ≥ 48px — палец, не мышь.

### Кнопки

| Вариант | Заливка | Текст | Где |
|---|---|---|---|
| `primary` | `ink` (свет) / `#F3F3F4` (тьма) | инверсный | Главное действие, одно на экран |
| `outline` | прозрачная + `hairline` | `ink` | Второе действие рядом |
| `soft` | `canvas-soft` / `surface-raised` | `ink` | Утилитарные, чипы-ссылки |

Все — `rounded-full`, высота 48px, горизонтальный паддинг 16px.
**Акцент никогда не используется для CTA** — только для сигналов (новое, срочно, готово).

### Чипы и бейджи

`rounded-full`, `label` 12/600. На фото — полупрозрачная подложка `rgba(115,115,115,0.56)`.

### Пустые состояния

Проектировать наравне с заполненными — **на демо данных будет мало**.
Формула: иконка `text-faint` → строка `body` что произойдёт → кнопка `soft` действия.

## 4. Экраны

**Главная** — шапка `2026 ⌄` + аватар. Далее секции:
активные заявки (компактные карточки-документы) → ближайшие события (карточки-обложки) →
рекомендованные возможности → широкая карточка-вход в матчинг.

**Заявки** — сегмент-контрол «Активные / История». Список карточек-документов.
FAB-пилюля «Новая заявка» → боттом-шит с сеткой шаблонов (иконка + название).

**Форма заявки** — полноэкранная, поля рендерятся из `schema_json`. Один вопрос — один блок.
Внизу липкая пилюля «Отправить».

**Заявка (трекинг)** — заголовок, номер, вертикальный степпер, при `ISSUED` — карточка
документа с кнопкой «Открыть PDF».

**Чат** — см. выше. Стартовый экран: три подсказки-пилюли с примерами вопросов.

**Люди** — колода на весь экран, сверху переключатель «Колода / Мои матчи / Наставник».

**Деканат** — тот же каркас, другой корень: очередь, фильтры-чипы сверху, карточки заявок,
действия в боттом-шите.

## 5. Специфика мини-приложения MAX

- Тёмная тема — по умолчанию, не опция
- `safe-area-inset-top/bottom` — нижняя навигация обязана учитывать
- Системная кнопка «Назад» (`WebApp.BackButton`) — **своей кнопки назад в шапке нет**
- Скелетоны до `WebApp.ready()`, иначе виден системный лоадер поверх пустоты
- Нет `hover` — все состояния через `:active` и анимацию масштаба (`whileTap`)
- Тач-цели ≥ 44px, фактически берём 48px
- Клавиатура перекрывает низ — поле ввода чата поднимается, навигация прячется

## 6. Интеграция присланных компонентов

⚠️ Оба написаны под **Next.js**, у нас **Vite**. Адаптация обязательна:

| Что | Заменить на |
|---|---|
| `"use client"` | удалить — директива только для Next |
| `import Image from "next/image"` | обычный `<img>` + обёртка с `aspect-ratio` |
| `fill` / `sizes` | `className="absolute inset-0 w-full h-full object-cover"` |
| `@phosphor-icons/react` | **`lucide-react`** — одна иконочная библиотека на проект |

### `expanding-tabs` → нижняя навигация

Берём почти как есть. Правки:
- убрать обёртку `min-h-screen ... items-center justify-center` — это демо-скаффолд
- контейнер сделать `fixed bottom-0 inset-x-0` + `pb-[env(safe-area-inset-bottom)]`
- иконки: `Home`, `FileText`, `Users`, `MessageCircle` из lucide
- цвета из токенов выше вместо захардкоженных `#E3E3E8` / `#0E0E0F`
- добавить `aria-current="page"`, роль `tablist` уже есть

### `thumbnail-carousel` → галерея в карточке возможности

Низкий приоритет, но подходит для хакатона с несколькими изображениями и для фотоотчёта
с события. Правки: `next/image` → `<img>`, размеры слайдов сделать `w-full` вместо
фиксированных 320/384, автопрокрутку выключить (в мини-апке она раздражает).

## 7. Стек фронта и установка

Проект ещё не создан. Команды на момент старта реализации:

```bash
npm create vite@latest frontend -- --template react-ts
cd frontend
npm i -D tailwindcss @tailwindcss/vite
npm i framer-motion lucide-react
npx shadcn@latest init
```

**Алиас `@/*`** прописать в `tsconfig.json` и `vite.config.ts` — без него импорты
`@/components/ui/...` из присланных компонентов не разрешатся.

### Почему компоненты кладём именно в `src/components/ui/`

Это путь по умолчанию для shadcn (`components.json` → `aliases.ui`). CLI пишет туда
сгенерированные примитивы, и все сниппеты в экосистеме импортируют оттуда.
Если положить в другое место — каждый `npx shadcn add ...` будет создавать параллельную
папку, и в проекте окажется два набора одних и тех же компонентов.

Разделение: `src/components/ui/` — примитивы (кнопка, поле, шит, табы),
`src/features/*/components/` — экранные компоненты, знающие про домен.

### Шрифт

Inter Variable через `@fontsource-variable/inter` (локально, без обращения к Google Fonts —
внутри мессенджера внешние шрифты грузятся медленно и мигают).
