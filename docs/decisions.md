# Журнал решений (ADR)

Формат: решение — обоснование одной-двумя строками. Дополнять по ходу.
Пользователь делегировал принятие решений — фиксировать здесь, а не спрашивать.

---

### 001. Продукт — мини-апка, бот — транспорт
Чат с ассистентом живёт **внутри мини-приложения** отдельным экраном, а не в чате мессенджера.
Бот отвечает только за: вход (`open_app`), push-уведомления, доставку PDF файлом.
Сложных диалогов бот не ведёт.
*Причина:* решение пользователя от 23.09.2026.

### 002. Ассистент — интерфейс ко всем модулям, а не отдельный раздел
RAG + tool calling во внутренние API. «Где моя справка?» → вызов `get_my_requests()`,
а не поиск по регламентам.
*Причина:* превращает набор CRUD-ов в продукт; лучшая минута демо.

### 003. Заявки — движок JSON-шаблонов, а не набор форм
Новый тип справки = строка в БД. Один динамический валидатор на бэке + один рендерер на фронте.
*Причина:* главный аргумент на защите; восемь типов справок стоят как один.

### 004. Матчинг — свайп по интентам (объявлениям), а не по людям
*Причина:* чинит холодный старт (1 человек = 3–5 карточек), снимает вопрос модерации
и харассмента, даёт понятный повод написать.

### 005. Buddy-автоматч вместо отдельного модуля ивентов
Ивенты были нужны как лекарство от холодного старта матчинга. Пользователь их не взял.
Замена: свайп по интентам + гарантированный автоматч наставника первокурснику.
*Причина:* на демо в базе 5 аккаунтов — колода не должна быть пустой.

### 006. Календарь вуза вместо расписания пар
События: собрания, дедлайны, встречи. С таргетингом по факультету/курсу/группе.
*Причина:* расписание есть везде и не впечатляет; календарь вуза — реальная дыра.

### 007. Рекомендации — взвешенный скоринг в SQL, не ML
*Причина:* объясняется за 15 секунд, не падает на пустых данных, экономит дни.

### 008. Бэкенд на Python + FastAPI
*Причина:* RAG-слой (эмбеддинги, чанкинг) на Python живёт комфортнее; команда знает Python.
Потеря общих типов с фронтом компенсируется генерацией из `openapi.json`.

### 009. Эмбеддинги локальные (multilingual-e5-base), LLM за абстракцией
*Причина:* смена LLM-провайдера не требует переиндексации базы знаний;
эмбеддинги бесплатны и работают офлайн.

### 010. Гибридный поиск (вектор + полнотекст, RRF), не чистый вектор
*Причина:* на базе в 50 документов вектор промахивается мимо точных формулировок
(«пункт 4.2», «форма 26»).

### 011. Все исходящие сообщения — только через outbox-очередь
*Причина:* лимит 30 rps, ретраи при «медиа ещё обрабатывается», тихие часы,
выживание при рестарте.

### 012. Авторизация тулов ассистента — в слое исполнения, не у модели
`student_id` из ContextVar; в схеме тула поля «чей» нет.
*Причина:* иначе «покажи заявки Иванова» становится рабочим эксплойтом.

### 013. Ассистент не совершает действий без подтверждения
`start_request` возвращает диплинк на форму, а не создаёт заявку.
*Причина:* галлюцинация не должна уметь подать заявление на академ.

### 014. PDF без ЭЦП + QR на страницу проверки подлинности
На защите проговаривать честно: юридическую силу даёт ЭЦП, показан стыкуемый механизм.
*Причина:* вопрос «а это законно?» прилетит гарантированно; лучше ответить первыми.

### 015. Роль деканата обязательна в MVP
*Причина:* без неё заявки — форма в никуда; демо в две стороны на двух устройствах
это вау-момент всего проекта.

### 016. Карта здания вырезана из скоупа
*Причина:* высокие трудозатраты (планы этажей, позиционирование внутри помещений)
при почти нулевой ценности. Компромисс при необходимости — статичная картинка
с подсвеченной аудиторией в карточке события.

### 017. LLM — Yandex Foundation Models через OpenAI-совместимый эндпоинт
Ключ выдан пользователем 23.09.2026. Работаем через `https://ai.api.cloud.yandex.net/v1`
SDK `openai` с `base_url`, а не через нативный `foundationModels/v1/completion`.
*Причина:* стандартный формат `tools`, готовый SDK, меньше своего кода, проще сменить провайдера.
Нативный эндпоинт остаётся запасным путём.
*Следствие:* prompt caching недоступен — системный промпт и описания тулов держать компактными,
историю диалога агрессивно обрезать.

### 018. Эмбеддинги — Yandex, а не локальные
`text-search-doc/latest` для чанков, `text-search-query/latest` для запросов (разные модели, не путать).
*Причина:* снимает 1–2 ГБ RAM с деплоя и риск «модель не влезла на VPS»; ключ уже есть.
Локальный `multilingual-e5-base` остаётся за тем же интерфейсом как запасной.
*Обязательно:* размерность вектора подтвердить тестовым вызовом ДО написания миграции.

### 019. RAG принудительный, а не инструмент на выбор модели
`search_regulations` убран из списка тулов. Поиск по регламентам выполняется **безусловно**
на каждый вопрос, фрагменты подмешиваются в системное сообщение до вызова модели.
Тулы остаются только для личных данных и действий.
*Причина:* проверка 24.09.2026 показала, что YandexGPT не доводит цепочку инструментов до конца —
на составном вопросе вызвал один тул, ответил и потерял вторую часть. Принудительный RAG
гарантирует заземление и убирает риск выдуманного регламента. Детали в `docs/05-llm-notes.md`.

### 020. Цикл тулов ограничен 4 итерациями
*Причина:* цепочка ненадёжна, бесконечный цикл недопустим; после лимита отдаём что собрали.

### 021. Размерность вектора — 256, столбец `vector(256)`
*Причина:* подтверждено живым вызовом обеих моделей эмбеддингов 24.09.2026.

### 022. Ручная отладка API — payload только файлом, не inline в bash
*Причина:* кириллица inline в `curl -d` на этой машине повреждается, симптомы маскируются
под неисправность модели (потеряно много времени). Файлы в `tmp/`, gitignored.
Боевого кода не касается — Python-клиенты кодируют корректно.

### 023. Тёмная тема — основная, светлая вторичная
*Причина:* мини-апка открывается внутри мессенджера с телефона, чаще вечером и в тёмном клиенте.
Референс Panora задаёт тон, Mobbin даёт структурную грамматику.

### 024. Два визуальных языка на один продукт
Фид (Главная, Люди) — фотоцентричный язык Panora. Документы (Заявки, Чат, деканат) —
плоский типографический язык Mobbin. Общая база: пилюли, радиус 24/16, Inter 650/450/300.
*Причина:* бюрократия должна читаться, а события и возможности — продаваться картинкой.

### 025. Тени разрешены только в тёмной теме
Светлая — строго бестеневая по Mobbin. Тёмная — заливка + внутренний верхний блик + мягкая тень,
иначе слои слипаются на чёрном. Приём взят из присланного `expanding-tabs`.

### 026. Нижняя навигация — `expanding-tabs`, четыре таба
Главная · Заявки · Люди · Чат. Профиль — аватар в шапке, не таб.
*Причина:* пять пилюль не помещаются на 320px; присланный компонент совпадает с нижним
баром Panora — это один и тот же паттерн.

### 027. Иконки — только `lucide-react`
`@phosphor-icons/react` из присланного компонента заменяем.
*Причина:* одна иконочная библиотека на проект; lucide идёт со shadcn по умолчанию.

### 028. Семантическая палитра статусов добавлена сверх Mobbin
У Mobbin её нет, но заявки без статусов не работают. Правило: статус несёт текст и тинт-чип,
цвет только на терминальных состояниях, карточка целиком не красится.

### 029. Акцент не используется для CTA
Главное действие — ink-пилюля. Акцент только для сигналов: новое, срочно, готово.
*Причина:* прямое правило Mobbin, держит интерфейс спокойным.

### 030. Детерминированный предзапрос данных перед вызовом модели
По ключевым словам вопроса бэкенд сам выполняет нужный инструмент и кладёт результат
в системное сообщение — ещё до обращения к модели. Инструменты при этом остаются доступными.
*Причина:* на проверке модель на вопрос «какие идут хакатоны» не вызвала ничего
и **выдумала три несуществующих мероприятия**. Предзапрос убирает саму возможность:
выдумывать нечего, факты уже в контексте. Это расширение решения 019 с регламентов на данные.

### 031. Санация ответа и повторный проход при отказе
Из текста вырезаются псевдо-вызовы инструментов (модель писала `[escalate_to_human]`
прямо в ответ) и голые JSON-строки. Если инструменты дали данные, а модель всё равно
ответила «не знаю» — делается один проход без инструментов с данными в открытом виде.
*Причина:* наблюдаемое поведение YandexGPT — теряет результат вызова.

### 032. Эскалация в деканат защищена от преждевременного вызова
Если `escalate_to_human` вызван первым, а формулировка указывает на конкретный инструмент,
вместо создания обращения возвращается подсказка вызвать нужный инструмент.
*Причина:* на «Где моя заявка?» модель создавала обращение в деканат вместо чтения статуса.

### 033. Источники фильтруются по пересечению с ответом
Под ответом показываются только те фрагменты базы знаний, которые реально отразились
в тексте (≥3 общих значимых слова).
*Причина:* под ответом про хакатоны выводились ссылки на «Материальную помощь».

### 034. Фон главной — «байкальский лёд» на WebGL-шейдере
На главном экране за контентом на весь вьюпорт течёт mesh-градиент
(`@paper-design/shaders-react`) в цветах байкальского льда; при прокрутке фон стоит.
Остальные экраны — на плоском канвасе: версия с фоном везде была опробована и
отвергнута — на формах и в длинных ответах ассистента текст читался хуже.
При `prefers-reduced-motion` фон не останавливается, а замедляется втрое: медленная
смена цвета — не резкое движение; в Windows с выключенными эффектами анимации
иначе фон стоял намертво.
*Причина:* плоский фон выглядел шаблонно; привязка к Байкалу даёт узнаваемость
именно иркутского вуза. Частицы и сетки из точек отвергнуты — клише и нагрузка
на телефон внутри вебвью. Шейдер считает не больше 400 тыс. пикселей — размытый
градиент неотличим от полного разрешения.

### 035. Афиша на главной: карусель обложек и раскрывающаяся карточка
События вуза и конкурсы идут одной лентой по дате. Карусель листается нативным
scroll-snap, а масштаб, наклон, затемнение и параллакс обложек вычисляются из
позиции прокрутки. Тап по центральной обложке раскрывает её на весь экран
(общий `layoutId` во framer-motion), внутри можно листать дальше свайпом.
*Причина:* список карточек «Ближайшее» не давал ощущения живого кампуса. Жест-
листание — нативный скролл, а не drag на JS: в вебвью он плавнее и не спорит
с системными жестами.

### 036. Анимации при прокрутке — на CSS scroll-timeline
Карточки и заголовки секций проявляются при прокрутке через
`animation-timeline: view()`, шапка главной уходит через `scroll(root)`.
*Причина:* такая анимация привязана к положению скролла, а не ко времени, и не
может застрять на полпути при троттлинге вебвью (см. проблему с онбордингом).
Где свойство не поддерживается, контент просто стоит на месте без анимации.
Сдвиг — свойствами `translate`/`scale`, чтобы не перебивать inline-`transform`
от framer-motion.

### 037. Обложки хранятся в приложении, а не на Unsplash
Unsplash из России не открывается (таймаут), и эксперты увидели бы пустые
градиенты. Снимки взяты с Wikimedia Commons под свободными лицензиями и лежат
в `frontend/public/covers/`, авторы — в `docs/photo-credits.md`.

### 038. Даты демо-событий обновляются при каждом старте
Даты в демо заданы как «через N дней» и раньше считались один раз. За неделю
до проверки афиша опустела бы. Теперь сид сдвигает даты существующих демо-записей
от текущего дня (по заголовку; пользовательские записи не трогаются). Час
события — иркутский (UTC+8), а не UTC: иначе ярмарка «в 11:00» показывалась в 19:00.

### 039. Запасной механизм анимаций при прокрутке
На телефоне пользователя эффекта не было: `animation-timeline` поддерживают не все
мобильные вебвью. `src/shared/scroll-motion.ts` проверяет поддержку: есть — класс
`.sda` и CSS-таймлайны, нет — класс `.js-reveal` и IntersectionObserver, который
ставит `.is-in` при появлении карточки. Позиция скролла в JS не читается,
анимируются только transform и opacity.

### 040. Главная без шейдерного фона
Фон «байкальский лёд» (решение 034) убран по отзыву: на телефоне он выглядел
грязно-синим и спорил с обложками афиши. Цвет на главной теперь даёт только
свечение активной обложки за каруселью. Зависимость `@paper-design/shaders-react`
удалена.

### 041. Учебный блок: расписание, «мой день», баллы, корпуса
Главный пробел по сравнению с победителями 2025 года — расписания не было.
Новые таблицы `schedule_slot`, `grade_item`, `building` (создаются `create_all`,
миграции не нужны). Время пар хранится строкой «HH:MM» в местном времени: сетка
звонков не абсолютное время. Чётность недели считается от недели 1 сентября.
Бот напоминает за 15 минут до *первой* пары дня — перед каждой было бы спамом.

### 042. Билет на событие — короткий подписанный код
Код `T<id записи>-<5 символов HMAC>`: без секрета не подделать, а продиктовать
на входе можно, если камера не работает. QR рисуется на сервере SVG той же
библиотекой, что и в PDF. Проверка — на экране «Деканат».

### 043. «Поделиться» через личку с ботом
Бот не может писать в чужие групповые чаты. Поэтому карточка события приходит
студенту в личку со ссылкой `max.ru/<бот>?startapp=event_<id>`, дальше — обычное
«Переслать». Вне мессенджера — системное меню `navigator.share` или копирование.

### 044. Опросы старосты
Староста — отдельная таблица `group_head` (в проде — из деканата). Опрос уходит
всей группе сообщением бота с кнопкой в приложение, с учётом тихих часов.
Тихие часы теперь считаются по иркутскому времени, а не по UTC.

### 045. Голосовой вопрос ассистенту — PCM из браузера в SpeechKit
MediaRecorder отдаёт WebM, который SpeechKit не принимает, а ffmpeg в образе —
лишние 80 МБ. Звук снимается через Web Audio, частота понижается до 16 кГц в
браузере, сервер пересылает сырые байты в SpeechKit (тот же ключ, что у LLM).

### 046. Подробности событий и возможностей — JSON-колонка
«Куда прийти, что взять, как участвовать, к кому обращаться» хранится в
`details_json` у `calendar_event` и `opportunity`. Колонка добавляется на старте
идемпотентным `ALTER TABLE … ADD COLUMN IF NOT EXISTS`: `create_all` новые колонки
в существующие таблицы не добавляет, а миграций в проекте нет. Демо-тексты —
`backend/app/seed/details.py`; телефонов и почт нет, чтобы не попасть в чужой номер.
Карточки «Стоит посмотреть» раскрываются той же полноэкранной карточкой, что афиша,
с собственным префиксом `layoutId`, чтобы не спорить с каруселью.

### 047. Иконки типов заявок — «матовое стекло» вместо эмодзи
Эмодзи выглядели случайно и по-разному рисовались на разных телефонах.
`components/ui/glass-icon.tsx`: набор из 9 иконок, собранных слоями на сетке 64×64 —
тёмная подложка, белый «бумажный» предмет, матовая панель с настоящим
`backdrop-filter`, белые детали сверху; всё на светлой плитке, иначе в тёмной теме
тёмное стекло сливалось с карточкой. Стиль — по референсу пользователя, рисунки свои.

### 048. Хостинг — российский VPS, HTTPS через Caddy и sslip.io
ngrok не пускает агентов с российских IP (`ERR_NGROK_9040`). Cloudflare, включая
quick-туннель, крупные российские провайдеры с июня 2025 обрывают примерно после
16 КБ: у проверяющего вместо приложения был бы белый экран. Зарубежные хостинги
из России тоже работают с перебоями. Поэтому — VPS в российском дата-центре.
Домен не покупается (FAQ хакатона, п. 17): `<ip-через-дефисы>.sslip.io` сам указывает
на IP, Caddy получает на него сертификат Let's Encrypt. Образы собираются на машине
разработчика и переносятся `docker save | ssh docker load`: на 1 ГБ памяти сборка
фронтенда может не влезть. Скрипты: `scripts/vps_bootstrap.py`, `scripts/deploy_vps.sh`.
Порты базы и приложения привязаны к `127.0.0.1` — наружу смотрит только Caddy.

### 049. Сторож вебхука
MAX молча отписывает бота, если вебхук 8 часов подряд не отвечает 200, а при смене
адреса подписки копятся и дублируют обновления. `ensure_webhook` в
`workers/scheduler.py` при старте и каждые 30 минут оставляет ровно одну подписку —
на `MINIAPP_PUBLIC_URL`. Включается `BOT_WEBHOOK_AUTOSUBSCRIBE=true` только на сервере:
локальный запуск с этим флагом увёл бы бота на временный адрес.

### 050. Раздача фронтенда только из папки сборки
Обработчик SPA собирал путь `FRONTEND_DIST / full_path` без проверки, и запрос
`/..%2F..%2F..%2Fetc%2Fpasswd` отдавал любой файл контейнера — включая выданные
справки студентов. Теперь путь проходит `resolve()` и должен лежать внутри папки
сборки, иначе отдаётся `index.html`. Найдено аудитом перед сдачей.

### 051. Dev-вход — только тестовые id 900000–999999
Вход по `dev:<id>:<Имя>` без подписи MAX пускал любой id: на публичном адресе можно
было представиться настоящим пользователем и читать его заявки и справки. Режим не
выключен — на нём держатся проверка в браузере, смоук-тест и доступ экспертов вне
MAX, — но сужен до тестового диапазона. Границы — одна константа
`TEST_USER_ID_MIN/MAX` в `core/config.py`; её же использует очередь уведомлений,
чтобы не слать в несуществующие аккаунты. Диапазон расширен с 900000–900999 под
демо-вход со случайным id на браузер: 900 вариантов дали бы совпадения уже при
20 экспертах.
Настоящие id MAX, которые встречались, — восьмизначные. Во фронтенде границы
продублированы (`shared/max.ts`): сохранённый раньше нетестовый id сбрасывается
на 900001, а в профиле такой id не применить. Цена: команда больше не может войти
в браузере под своим настоящим id MAX.

### 052. Подпись запуска живёт час, 401 — экран «Сессия устарела»
MAX выдаёт подпись один раз при открытии приложения. При TTL 15 минут эксперт
посреди сценария получал 401 и сырую ошибку. TTL — 3600 секунд (рекомендация
документации Bridge). Любой 401 в `shared/api.ts` поднимает общий флаг, и `App`
показывает полноэкранную заглушку вместо экрана. Внутри MAX главная кнопка —
«Закрыть приложение»: перезагрузка страницы отдаёт ту же протухшую подпись.

### 053. Секрет вебхука: неверный — 403, отсутствующий — по флагу
Раньше для запроса без заголовка `X-Max-Bot-Api-Secret` проверка просто не
выполнялась, а секрет в `.env` был пуст — поддельные события мог прислать кто
угодно. Теперь неверный секрет всегда получает 403 без обработки (раньше —
молчаливые 200). Без заголовка решает `MAX_WEBHOOK_REQUIRE_SECRET`, по умолчанию
`false`: раз секрет был пуст, подписка бота создана без него, MAX заголовок пока
не шлёт, и строгий режим выключил бы бота. Такой запрос принимается, в лог один раз
пишется предупреждение, а первый вебхук после старта отмечает, был ли заголовок
(значение — никогда). Секрет читается только из заголовка: из строки запроса он
оседал бы в журнале доступа. Запросы с неверным секретом «первый вебхук» не
занимают — смоук после выкладки шлёт именно такой. В локальном `.env` сгенерирован
секрет по формату схемы MAX (5–256 символов `[A-Za-z0-9_-]`); к MAX он уйдёт при
следующей подписке, после неё и строки «заголовок … есть» в логе флаг можно включать.

### 054. open_app → ссылка при любом отказе 4xx
Раньше к кнопке-ссылке переходили только при ошибке про `webApp`; любой другой отказ
4xx отправлял уведомление в ретраи очереди, где оно падало так же и не доходило
никогда. Теперь при любом 4xx это сообщение уходит со ссылкой, а open_app глобально
выключается по-прежнему только ошибкой про `webApp`. На 5xx — ретрай целиком.

### 055. Демо-вход для экспертов: своя копия студента на аккаунт
Кодов привязки четыре, они одноразовые, и смоук-тест занимает главный — второй же
эксперт получал «код уже использован». Теперь главная кнопка онбординга —
«Попробовать как студент (демо)»: `POST /api/binding/demo` (включается `DEMO_MODE`,
по умолчанию `true`) копирует шаблонного студента (Петрова Анна, Б-25-1,
`DEMO_TEMPLATE_RECORD_BOOK` в `seed/demo.py`) вместе с баллами и правами старосты
и привязывает копию к аккаунту. Зачётка — `DEMO-<app_user.id>`, она же признак
копии во всём коде (`modules/demo/service.py`). Копия одна на аккаунт, без лимита
по времени: уже привязанный аккаунт получает свой профиль (лимит «3 в час» из плана
не нужен). Двойное нажатие упирается в уникальность зачётки — точка сохранения
и возврат уже созданной копии.
ФИО копии — из профиля MAX (`first_name/last_name` подписи запуска): в очереди
деканата и в PDF эксперт видит себя, а не пятнадцатую «Петрову». Без имени или
с заглушкой dev-входа («Dev») — имя шаблона. Отчество не выдумываем.
Копии живут в группе оригинала (иначе пропали бы расписание, опросы и афиша),
но исключены из всего, что касается группы целиком: рассылки опросов старосты
(опрос демо-старосты не уходит никому и виден только автору, экран так и говорит),
напоминания о парах (первая пара в 08:00 по Иркутску — 03:00 МСК), счётчик «человек
в приложении», голоса в чужих опросах, пул наставников buddy-матчинга (бот
знакомил бы экспертов друг с другом). Колода «Людей» общая: отклик там взаимный.
Предохранитель — `DEMO_COPIES_PER_HOUR=60` копий в час на сервер (в памяти): скрипт
с тестовыми id иначе набил бы базу тысячами копий. `reset_demo.sh` удаляет копии
и всё, что на них ссылается.
В браузере вне MAX каждому браузеру — свой случайный тестовый id 901000–999999
в localStorage (`getDevUser`): раньше все были пользователем 900001 и видели заявки
друг друга. Фиксированные 900001–900999 остались смоук-тесту и быстрым кнопкам.

### 056. Роль деканата в один тап — только демо-профилю, очередь — только своя
`POST /api/binding/demo-staff` даёт права кода STAFF-002 (может выдавать) без ввода
кода, но только аккаунту с демо-копией: настоящий сотрудник входит по коду.
Кнопка «Включить роль деканата (демо)» — в профиле и на экране «Деканат», который
для не-сотрудника теперь объясняет, что это за раздел, а не показывает пустую
очередь поверх ошибки 403. Аккаунт с демо-копией в роли деканата (как бы он её ни
получил) видит в очереди и может двигать только заявки своей копии: копии названы
по профилям MAX, и общая очередь раскрыла бы одному эксперту имена и заявки
остальных. Заодно свою заявку не надо искать среди чужих. Сотрудники по кодам
без демо-копии видят всю очередь, как раньше.

### 057. Подписанная ссылка входа от бота
Пока организаторы не привязали мини-приложение к боту, кнопка `open_app` не
работает, и бот шлёт обычную ссылку — приложение открывается в браузере без
подписи MAX. Там человек становился тестовым пользователем 9xxxxx, и главный
сценарий «справка файлом в чат» не доходил до конца: уведомления тестовым id не
отправляются, а настоящим id без подписи не представиться (решение про dev-вход).
Теперь кнопка-ссылка (запасной путь `send_with_app_button`, по нему идут и
приветствие бота, и уведомления) ведёт на `MINIAPP_PUBLIC_URL/?lt=<id>.<exp>.<sig>`:
id собеседника, конец срока (unix) и `hex(HMAC_SHA256(секрет, "<id>.<exp>"))`.
Бот выдаёт токен только тому, кому пишет, так что id в нём — настоящий
пользователь MAX, как в подписи запуска.
- **Секрет** — `LINK_SECRET`; пустой выводится как `HMAC_SHA256("CampusLinkToken",
  MAX_BOT_TOKEN)`: ручного секрета заводить не нужно, и с ключом подписи запуска
  (`WebAppData`) он не совпадает. Смена секрета или токена бота гасит все ссылки.
- **Срок** — сутки (`LINK_TTL_SECONDS`): ссылка из вчерашнего уведомления ещё
  открывается, а утёкшая перестаёт работать на следующий день. Истёкший токен —
  401 и экран «Ссылка устарела — напишите боту /start».
- **Сервер** принимает `Authorization: MaxLink <токен>`: сначала формат (регуляркой —
  `compare_digest` не сравнивает строки с не-ASCII), потом подпись constant-time,
  потом срок. Без кеша проверок: HMAC дешёвый, а кеш на 5 минут продлил бы жизнь
  истёкшему токену. Имени в токене нет — его берём из профиля, который бот записал
  по апдейту MAX, чтобы демо-копия называлась по человеку (решение 055).
- **Фронтенд** забирает `lt` до первого запроса, сразу убирает его из адресной строки
  (`history.replaceState`) и хранит в `sessionStorage` — только эта вкладка. Внутри
  MAX токен игнорируется: настоящая подпись главнее. Метка в углу — «Браузер · вход
  через бота», переключатель тестового пользователя в этом режиме скрыт.
- **Токен не логируется:** фильтр на журнале доступа uvicorn заменяет значение на
  `lt=***`, при отказе MAX на кнопке-ссылке в журнал идёт только код ответа,
  `<meta name="referrer">` не отдаёт полный адрес чужим сайтам в старых вебвью.
- **Пересылаемые сообщения — без токена.** Карточку события («Поделиться»)
  пересылают в чат группы; ссылка со входом отправителя пустила бы в его аккаунт
  всех, кто её откроет. Такие виды уведомлений перечислены в `FORWARDED_KINDS`.
  Обычное уведомление человек тоже может переслать — это осознанный риск: ссылка
  даёт вход только в его аккаунт и только на сутки.
После привязки приложения к боту путь не мешает: кнопка снова `open_app`, вход —
по подписи запуска, ссылки со входом бот больше не шлёт.

### 058. Кнопка «Открыть заявку» ведёт в саму заявку
Кнопка `open_app` уходила как `{"type", "text"}`, а по схеме MAX (`OpenAppButton`)
поле `web_app` — имя бота с мини-приложением — обязательное. Ошибка «Field 'webApp'
cannot be null», которую мы списывали на непривязанное приложение, почти наверняка
из-за него. Теперь кнопка — `{"type":"open_app","text","web_app","payload"}`.
- **Имя бота** — `MAX_BOT_USERNAME` (по умолчанию `t355_hakaton_max_bot`); пусто —
  один раз `GET /me` с кешем в памяти. Неудача `/me` не кешируется, а сообщение
  уходит ссылкой. Тем же именем строится диплинк «Поделиться событием» — константа
  в `routes_campus.py` убрана.
- **Payload** — экран, на котором открыть приложение: `req_<номер>` у уведомлений
  о заявке, `event_<id>` у карточки события, `group` у опроса старосты, `schedule`
  у напоминания о паре. Параметр `enqueue(open_app_payload=…)` хранится в outbox
  рядом с подписью кнопки. Формат MAX — до 512 символов `[A-Za-z0-9_-]`; номер заявки
  `2026-000123` в него укладывается. Параметр не по формату не отправляется: MAX
  отклонил бы всё сообщение, а главная лучше, чем ничего.
- **Запасная ссылка** (решение 054) ведёт туда же: `/?lt=…&WebAppStartParam=req_…`.
  `WebAppStartParam` — GET-параметр, в котором MAX сам передаёт стартовый параметр
  в адрес мини-приложения, поэтому фронт (`getStartParam`) читает сначала подпись
  запуска, потом адрес — одна ветка на оба пути. Параметр только выбирает экран:
  чужая заявка по-прежнему 404 от сервера, на экране — «Заявка не найдена» и список.
- **Диплинк — один раз за запуск.** `navigate` из react-router меняется при каждом
  переходе, и эффект диплинка срабатывал заново: из открытой по ссылке заявки нельзя
  было уйти, а несуществующая гоняла по кругу «заявка → 404 → список → заявка».
  Флаг `useRef` в `App.tsx`. Ошибка была и раньше (`schedule`, `request_…` внутри
  MAX), просто без ссылок из бота до неё почти не доходили.
- Цепочка «open_app → ссылка → текст» не менялась; её и новую кнопку проверяет
  `scripts/test_bot_buttons.py` с заглушкой вместо Bot API.
Не проверено: как живой MAX отвечает на кнопку с `web_app` — это видно только по
сообщению реальному пользователю. Если откажет с упоминанием webApp, open_app
выключится до рестарта и уведомления пойдут ссылкой, как сейчас.
Сообщение с PDF (`send_document`) осталось без кнопки: трёхшаговую отправку файла
перед сдачей не трогаем.

### 059. Автовыдача типовой справки — в том же запросе, а не фоновым автопилотом
План «демо-автопилота» (фоновая задача ведёт заявку по шагам 20–40 секунд) заменён:
задача со своей сессией погибает при рестарте, и заявка навсегда зависла бы
«на подписи». Вместо него — продуктовое правило: **типовые справки выдаются
автоматически, нетиповые идут через сотрудника**.
- **Флаг в шаблоне.** `request_template.auto_issue` (колонка, `ALTER … IF NOT EXISTS`
  при старте, как у `details_json`); в сиде он стоит у справки об обучении. Сид
  сбрасывает флаг, если его убрали из шаблона, — иначе он остался бы в базе.
- **Что считается нетиповым** — тоже данные: поле шаблона с `manual_review: true`,
  если его заполнили (значение не пустое и не равно значению по умолчанию).
  У справки об обучении это «Нужен оригинал с печатью» (бумагу готовит человек)
  и «Комментарий» (особая формулировка). Правило одно на сервере
  (`engine.can_auto_issue`) и в форме (`DynamicForm.isFilled`): форма заранее
  показывает, что будет — «Получить PDF сразу» или «Отправить заявку».
- **Один путь к PDF.** Тело `staff_issue` вынесено в `modules/requests/service.py`:
  `issue_document()` (подпись → PDF → «Выдана» → аудит) и `notify_issued()`.
  Кнопка сотрудника и автовыдача вызывают одно и то же. Автовыдача идёт через
  `engine.transition` по `ALLOWED_TRANSITIONS`: IN_REVIEW → SIGNING → READY → ISSUED,
  `actor_kind="system"`, выдающий — «Демо-деканат (автоматическая выдача)».
  В PDF в блоке подписи — «Выдано автоматически / без подписи сотрудника».
- **Сбой не ломает подачу.** Шаги автовыдачи — в SAVEPOINT (`begin_nested`). Если
  PDF не сформировался, откатываются только они: заявка остаётся «Отправлена»
  и уходит в очередь сотрудника. Проверено симуляцией сбоя внутри контейнера.
- **В чат — два сообщения, а не пять.** «Заявка типовая — документ выдан
  автоматически» с кнопкой «Открыть заявку», следом PDF файлом. Промежуточные
  статусы случились в одну секунду — слать их отдельно значило бы шуметь; они
  есть в истории заявки. Порядок гарантирует outbox: сообщения уходят по id.
- **Экран.** Сразу после подачи (`state.fresh` из формы) степпер проигрывает шаги
  по 0,65 с, потом появляются карточка документа и конфетти. Один раз на заявку
  (`sessionStorage`), при следующем входе — обычный вид.
- **Ассистент** в `list_request_templates` получает у таких шаблонов поле `issued`
  («сразу при подаче…»), иначе обещал бы три дня. Регрессия ассистента — 10/10.
Смоделировано (README, «Что смоделировано»): данные — синтетический справочник,
1С и подпись не подключены. Для продуктива — выгрузка контингента и УКЭП вуза.

### 060. Ассистент: ответ за 25 секунд, при сбое — выдержки, лимит 20 вопросов за 10 минут
httpx ждал модель до 120 с, а на экране всё это время висели три точки — выглядит
как зависание, прокси рвёт соединение раньше. Лимита не было, а адрес публичный
две недели: каждый вопрос — платный вызов Yandex, скрипт сжёг бы баланс, и вместе
с ним умерли бы ассистент, голос и эмбеддинги. Настоящий стриминг не делаем:
ответ сначала чистится и при отказе модели переспрашивается (решение 030).
- **Таймаут на весь ответ** — `asyncio.wait_for` вокруг поиска, предзапроса и цикла
  инструментов, `ASSISTANT_TIMEOUT_SECONDS=25`. Вопрос коммитится до обращения
  к модели; по таймауту транзакция откатывается — отмена могла прервать запрос к базе
  посреди выполнения. *Исправлено в 061:* здесь было «инструменты не пишут», а
  `escalate_to_human` пишет — создаёт обращение, и откат его стирал, оставляя кнопку.
- **Сбой или таймаут модели — не ошибка, а выдержки** из найденных регламентов
  с пометкой «Модель не ответила — вот что сказано в регламенте». Это цитата из
  базы знаний, а не ответ модели, и человек это видит. Не больше двух, по одной на
  документ, вторая — только такая же сильная, как первая. Выдержка берётся, только
  если в ней есть слова вопроса (грубая основа, без служебных слов): вектор находит
  «ближайшее» и к вопросу о погоде, а честное «в регламентах ничего не нашлось»
  лучше чужого регламента. Кнопки из предзапроса («Открыть заявку») сохраняются.
  Если завис сам поиск (эмбеддинг от Yandex), запасной поиск — только полнотекст
  по своей базе, по любому слову вопроса.
- **Лимит** — 20 вопросов за 10 минут на пользователя (`ASSISTANT_RATE_LIMIT`,
  `ASSISTANT_RATE_WINDOW_SECONDS`), память процесса, как у лимита кодов привязки.
  Сверх лимита — 429 `RATE_LIMITED` с человеческим текстом и `retry_after`; вопрос
  не сохраняется и в модель не уходит. Живой человек в лимит не упирается, а смоук
  и регрессия ассистента вместе — 14 вопросов от одного тестового id: два полных
  прогона подряд в пределах 10 минут упрутся в лимит, это ожидаемо.
- **Экран чата.** Вместо трёх точек — строка этапа: «Ищу в регламентах…» →
  «Сверяю с твоими данными…» → «Формулирую ответ…». Сервер прогресс не присылает,
  строки сменяются по времени (0 / 2,5 / 6 с), но в том порядке, в котором сервис
  и правда работает. Через 20 с без ответа — «Дольше обычного» и «Повторить»:
  зависший запрос бросается (`AbortController`) и уходит заново (на сервере повтор
  присоединяется к тому же ответу — решение 061). У сообщения об
  ошибке сети — тоже «Повторить»; у сообщения о лимите — нет, повтор его не лечит.
Проверено: подменой модели внутри контейнера (зависание, ошибка 500, зависший
эмбеддинг, вопрос мимо базы, лимит) и через стек FastAPI (`httpx.ASGITransport`);
вид экрана — снимками с подменой ответа в браузере. Регрессия ассистента — 10/10.

### 061. Защита ассистента, доработка: обращение не теряется, повтор не дублирует
Проверка решения 060 нашла пять дыр; закрыты так.
- **Обращение в деканат пишется в своей сессии и коммитится сразу.** Откат по
  таймауту стирал созданное `escalate_to_human` обращение, а кнопка «Обращение №…»
  и текст «Твои данные — по кнопке ниже» оставались: студент думал, что вопрос ушёл
  в деканат, кнопка вела в несуществующую заявку. Теперь запись идёт в отдельной
  сессии под `asyncio.shield` — отмена по таймауту её не обрывает, а запасной ответ
  ждёт её до 5 с и называет номер: «Вопрос уже передан в деканат — обращение №…».
  Кнопка появляется только после коммита. Выбрано вместо «после отката убрать
  кнопку»: студент явно просил передать вопрос, и терять его нельзя. Остальные
  инструменты только читают — откат основной транзакции ничего не теряет.
- **Повтор присоединяется к ответу, который уже готовится.** «Повторить» на экране
  появляется через 20 с, а запасной ответ сервера — через 25 с; брошенный запрос
  на сервере продолжал работать (отключение клиента его не прерывает), и повтор
  запускал второй вызов Yandex, второй вопрос в истории и второе списание лимита.
  Теперь тот же вопрос того же пользователя, пока на первый готовится ответ, ждёт
  этот ответ (`service._pending`). Кнопку на 20 с оставили: при обрыве связи повтор
  забирает ответ по новому соединению — ради этого она и нужна. Упал первый —
  второй отвечает сам. Память процесса, как у лимита: воркер у uvicorn один.
- **Очистка диалога во время ответа.** Раньше давала 500 на вставке ответа
  (внешний ключ на удалённый диалог). Ответ теперь сохраняется в точке сохранения
  (`begin_nested`): если диалога уже нет, ответ отдаётся, но не пишется. Очистка
  блокирует строки диалога (`FOR UPDATE`) и удаляет одним запросом — ответ, который
  как раз пишется, либо успевает раньше и удаляется со всеми, либо ждёт очистки.
  На экране кнопка очистки неактивна, пока готовится ответ, и это корзина, а не
  стрелка по кругу, — стрелка у «Повторить», их легко было перепутать.
- **Вопрос про свои данные** («где моя заявка на справку», отклики) по регламенту
  не отвечается: от него оставалось слово «справка», и запасной ответ цитировал
  справку для военкомата. Теперь для таких вопросов (те же ключевые слова, что
  у предзапроса `get_my_requests`/`get_my_matches`) выдержек нет — только кнопки
  к заявкам. Если таймаут наступил ещё в поиске, предзапрос добирается в запасном
  ответе, в тех же 5 секундах, что и полнотекстовый поиск.
- **Экран докручивается до самого низа.** Прокрутка к последнему сообщению
  оставляла его под прилипшим полем ввода — мгновенный отказ по лимиту при длинной
  истории было не видно. Теперь — до конца страницы.
- **`test_assistant.py`** сам привязывает тестового студента кодом A7K2-9M, если
  привязки нет (её снимает `reset_demo.sh` после смоука), а на 429 прерывается
  с подсказкой: смоук (4 вопроса) и регрессия (10) укладываются в лимит, второй
  прогон подряд — нет; лимит обнуляет `docker compose restart app`.
Проверено внутри контейнера подменой модели (21/21: эскалация + зависание, запись
обращения дольше таймаута, эскалация + ошибка модели, своя заявка при таймауте и при
зависшем поиске, очистка во время ответа и при незакоммиченном ответе, два
одинаковых вопроса разом, падение первого); по HTTP на настоящей модели — очистка
через 0,4 с после вопроса (оба 200) и повтор после брошенного запроса (присоединился,
в истории один вопрос); экран — снимками с подменой ответа (лимит виден над полем
ввода, корзина неактивна во время ответа).

### 062. Позиционирование: «Кампус — первокурснику», справка — крючок
Слоган: **«Кампус — первокурснику: справка файлом в чат, ответы по регламентам,
свои люди»**. Название «Цифровой кампус» убрано отовсюду: так назывались проекты,
занявшие 1-е и 3-е места трека в 2025 году (расписание + деканат + проекты), и
первый экран, повторяющий их, сливается с ними.
- **Почему не «деканат в чате».** Это было в плане, но текст трека — «развитие
  навыков, навигация на старте карьеры, безопасная среда», и «деканат в чате» не
  попадает ни в одно слово. Справку оставили крючком и главным сценарием, а слоган
  привязали к первокурснику: ассистент по регламентам и афиша — навигация на старте,
  «Люди» — безопасная среда.
- **Онбординг.** Вместо надписи капсом и «вузовской рутины» — заголовок «Справка из
  деканата — файлом в чат» и три отличия с пояснением, а не четыре экрана списком.
- **Главная.** Карточка справки стоит сразу под ближайшей парой, всегда, а не
  ~1300 px ниже и только при пустом списке заявок. Главная кнопка ведёт прямо
  в форму справки об обучении (`/requests/new/study_certificate`), ссылка под ней
  «Другие справки и заявления» — в каталог (две кнопки в ряд на экране 360 px
  переносили подпись). Кнопка — `bg-ink`, как у всех главных действий: акцент
  по дизайн-системе оставлен под сигналы.
- **Бот.** Из HELP убрано «Я — транспорт для приложения» — это наша архитектура,
  а не ценность для студента. Приветствие — гид из трёх шагов: открыть →
  «Попробовать как студент» → «Справка об обучении», PDF придёт сюда. При
  `DEMO_MODE=false` второй шаг — «введи код из деканата», иначе бот звал бы
  в кнопку, которой нет.
- **«Люди».** Под заголовком — «Только подтверждённые студенты вуза · контакт
  открывается при взаимном отклике». Это правда кода, а не обещание: колода,
  отклики и объявления требуют привязки (`BoundUserDep`), в карточке колоды только
  имя, фото, курс и факультет, `@username` — только в паре после взаимного свайпа.
- **Не тронуто.** Имя API «MAX Campus API» (адрес документации и паспорт в
  `DATA-API.yaml` на него ссылаются), промпт ассистента (в нём нет старого названия,
  а правка требует прогона регрессии на платной модели), `pyproject.toml` (правка
  сбросила бы слой `pip install` в образе и подтянула бы новые версии пакетов
  за два дня до сдачи).

### 063. Обязательный визуал перед сдачей: навигация, метки, приветствие
Правки из визуального аудита, которые попадают в видео и в самостоятельный проход
эксперта. Три из них требовали решения:
- **Нижнее меню скрыто на форме заявки и в карточке заявки.** На форме липкая кнопка
  «Отправить» висела над меню и закрывала поле комментария. Выбор шаблона в каталоге
  теперь — переход на `/requests/new/<ключ>`, а не состояние экрана: меню скрывается
  по адресу, системная «Назад» в MAX ведёт в каталог, шаблон передаётся с переходом,
  и форма открывается без мигания списка. В браузере системной «Назад» нет, поэтому
  в карточке заявки вне MAX — своя ссылка «Назад» (у формы она уже была).
  Каталог `/requests/new` — обычный экран, меню на нём осталось.
- **Плашка «DEV · вне MAX» — только по `?debug=1`.** Она наезжала на заголовок
  каждого экрана. Скрыть её не значит выдать тестовый вход за настоящий: тестовый
  пользователь виден в профиле, внизу профиля — «демонстрационная версия, данные
  смоделированы». Плашка «Браузер · вход через бота» оставлена: это настоящий
  пользователь MAX, и метка честно говорит, что открыт не мини-апп.
- **Приветствие по Иркутску.** Сервер считал час по UTC — утром по Иркутску
  выходило «Доброй ночи». Теперь `local(now).hour`; пока `/home` грузится, фронт
  показывает то же приветствие по UTC+8, а не «Привет», которое через секунду
  сменялось длинной фразой с переносом строки. Смоук проверяет приветствие.
- Остальное без развилок: скелетон карточки пары той же высоты (150 px), заголовок
  раскрытой карточки события не срезается (снизу 48 px под наезд текста), дедлайн —
  янтарный постер с полной датой «2 окт · 18:00» и числом целиком в рамке,
  «Куда и когда» — обычным регистром, «Мой билет» не показывается там, где регистрации
  нет, активная вкладка и выключенные переключатели в светлой теме видны,
  «4 этажа», ФИО в профиле — на двух строках, «Маршрут» в корпусах — мягкая кнопка.

### 064. Четыре чужих снимка заменены типографскими обложками
На четырёх обложках было видно, что это не ИГУ: водяной знак «© Tulane University»
(корпус юридического института и конкурс научных работ), американская волейбольная
команда (спорткомплекс и кубок), ярмарка в Дакке и ярмарка вакансий в Софии.
Продукты MAX показывают госорганам, и чужой вуз на фото бьёт по доверию.
*Решение:* снимки удалены, в сиде у этих карточек `cover_url` пустой — приложение
само рисует типографскую обложку (градиент, крупное число, дата), как у дедлайнов.
Искать замену на Commons не стали: снимков ИГУ под свободной лицензией мало,
а проверка лицензий перед сдачей не окупается. Четвёртым взят `employers.jpg`:

Обложки корпусов теперь обновляются из сида и в заполненной базе (как у событий

### 065. Сервер на недели проверки: сдвиг дат в процессе, логи с ротацией, ночная копия
Проверка идёт 30.09–14.10, финал 29.10, и всё это время стенд должен жить без рук.
Нашлись три вещи, которые ломались бы сами по себе:
- *Даты демо-событий* сдвигались только при старте (решение 038) — без перезапуска
  афиша за неделю уехала бы в прошлое. План предлагал ежедневный `docker compose
  restart` по cron, но рестарт обрывает запросы экспертов и фоновые задачи на лету.
  Вместо него — задача планировщика `demo_dates` (`workers/scheduler.py`): раз
  в 10 минут сверяет иркутскую дату и один раз в сутки, после полуночи по времени
  вуза, заново отсчитывает даты от сегодняшнего дня (`refresh_demo_dates` в сиде —
  тот же код, что при старте). «Завтра» в афише всегда остаётся завтрашним днём.
- *Демо-объявления «Людей»* получали срок 30 дней один раз, при первом сиде:
  созданные 23.09 истекли бы 23.10, до финала. Теперь при каждом старте и при
  ежедневном сдвиге объявления демо-авторов (`max_user_id < 0`) продлеваются на
  30 дней от текущего момента, а уже снятые по сроку включаются обратно — снять их
  иначе некому, войти под отрицательным id нельзя. Живые пользователи и демо-копии
  экспертов не затрагиваются.
- *Логи контейнеров* без лимита за месяц заняли бы диск VPS (10 ГБ). В
  `docker-compose.yml` всем сервисам — json-file по 10 МБ, три файла (якорь
  `x-logging`). Применяется при пересоздании контейнера — то есть со следующей выкладкой.

Резервная копия и подъём после перезагрузки — `scripts/vps_maintenance.sh`, его
запускают на сервере под root из `/opt/max-campus`; `deploy_vps.sh` не менялся.
Скрипт пишет `/etc/cron.d/max-campus` целиком (повторный запуск ничего не
дублирует): ночью `pg_dump -Fc` базы и архив тома `/data` (справки PDF без базы
бесполезны, база без справок отдаёт 410) в `/opt/max-campus/backups`, хранятся
7 последних; копия пишется во временный файл и становится копией, только если
`pg_dump` завершился успешно и `pg_restore -l` читает её оглавление, — оборванная
не вытеснит целые при ротации. `@reboot` — подстраховка `docker compose --profile vps
up -d --no-build`: `restart: unless-stopped` не поднимает контейнеры, остановленные
вручную. Копии лежат на том же диске — защищают от ошибки (лишний `reset_demo.sh`,
неудачная выкладка), но не от потери сервера; забрать к себе — `scp`.

### 066. Вуз — из настроек: название, часовой пояс, демо-наполнение
Масштабирование — 35 % продуктовой оценки, а тезис «новый вуз = `.env` + шаблоны +
регламенты» код не подтверждал: название ИГУ было зашито в `pdf.py`, UTC+8 — в
`core/dates.py` и дважды во фронтенде, а сид в пустую базу вуза положил бы синтетику.
*Решение:*
- `UNIVERSITY_NAME` и `UNIVERSITY_TZ_HOURS` в `core/config.py`, по умолчанию прежние
  значения (ИГУ, 8). Пояс — целое смещение от UTC (от −12 до 14), а не `ZoneInfo`:
  в России нет перехода на летнее время, а в slim-образе может не быть tzdata.
  Все места, где сервер считал «по Иркутску», уже шли через `dates.UNIVERSITY_TZ`.
- Фронтенд получает смещение в `/api/me` (`tz_offset_hours`) до первого экрана.
  По нему считаются текущая пара, приветствие и **все даты и время на экранах**
  (`shared/utils.ts`, обложки афиши). Раньше время событий показывалось по поясу
  телефона: эксперт из Москвы видел собрание в 09:00, а бот и расписание говорили
  14:00. Теперь время везде — вуза, как в сообщениях бота и в PDF.
- `SEED_DEMO_DATA` (по умолчанию `true`): при `false` сид создаёт только шаблоны
  заявок. Иначе в базе вуза настоящие студенты получили бы демо-баллы и расписание,
  первые четыре — демо-коды привязки, а их имена попали бы в объявления «Людей».
  Отдельный флаг, а не `DEMO_MODE`: кнопка демо-входа и демо-данные — разные вещи,
  на стенде включены обе. При `false` автовыдача подписывается «Деканат
  (автоматическая выдача)» — «демо» в подписи верно, только пока контингент синтетический.
- Документ внедрения назван `docs/05-rollout.md`, как в плане и на слайдах, хотя
  `05-llm-notes.md` уже есть: переименование сломало бы ссылки ради порядка файлов.
- Стоимость YandexGPT считается от замера, а не от догадки: шесть типовых вопросов
  дали один вызов модели, ~2 000 входных и ~60 выходных токенов на вопрос. В оценке
  взято 3 000 токенов с запасом на историю диалога, результат помечен как оценка.

Проверено: чистая база с `SEED_DEMO_DATA=false` → только 9 шаблонов, повторный старт
ничего не добавляет; отдельный экземпляр на временной базе — импорт CSV студентов,
коды привязки SQL-запросом из документа, привязка, автовыдача: в шапке PDF своё
название, выдал «Деканат (автоматическая выдача)», экраны учёбы отвечают 200 с пустыми
данными. Даты во фронтенде проверены под поясами Москвы, Иркутска и Нью-Йорка.

### 067. Публичный стенд против скрипта: лимиты по типу входа и адресу, размер запроса, квота вложений
Ревью безопасности нашло три способа сломать стенд без авторизации или с придуманным
тестовым id — все проверены вживую:
- *Демо-вход можно было закрыть всем.* Лимит копий был один на сервер (60 в час), а
  тестовые id 900000–999999 придумываются без счёта: 60 запросов — и каждый эксперт,
  включая вошедших из MAX, получал 429 на час. Теперь лимиты — только у тестовых id:
  120 копий в час на сервер и 10 с одного адреса (`DEMO_COPIES_PER_HOUR`,
  `DEMO_COPIES_PER_IP_HOUR`). Аккаунт MAX с подписью запуска или ссылкой бота не
  ограничивается: копия одна на аккаунт, а аккаунт не придумать. Браузерный путь
  остаётся уязвим к скрипту с многих адресов — это цена входа без регистрации.
- *Адрес клиента* — последний элемент `X-Forwarded-For`, и только если соседом был
  внутренний адрес (Caddy в сети Docker). Caddy не доверяет присланному клиентом
  заголовку и дописывает свой. Запрос изнутри сервера без заголовка (смоук-тест)
  лимитов по адресу не получает. Подбор кода привязки: к 5 попыткам в час на аккаунт
  добавлены 20 неудачных в час с адреса.
- *Размер тела не был ограничен:* 600 МБ в вебхук без секрета поднимали память
  процесса до 1,4 ГБ при 1 ГБ на сервере. ASGI-слой `BodySizeLimit`
  (`core/limits.py`): 1 МБ на запрос, 11 МБ на `/api/uploads`, Content-Length
  проверяется сразу, тело без него — по мере чтения; ответ 413 `PAYLOAD_TOO_LARGE`.
  Вложение пишется на диск кусками; квота — 20 файлов на студента, 500 МБ на сервер
  и 1 ГБ свободного места всегда (`UPLOADS_PER_STUDENT`, `UPLOADS_TOTAL_MB`), иначе
  ночная копия, хранящая `/data` семь раз, забила бы диск.
- Попутно: закешированная подпись запуска сверяется со сроком и на попадании в кеш —
  раньше кеш на 5 минут продлевал её до 65 минут. Ошибка валидации своих проверок
  (`field_validator`) отдавала 500: в `ctx` лежал объект исключения, JSON его не
  сериализовал. Теперь в `details.errors` — только `loc`, `msg`, `type`.

### 068. Права сотрудников: роль проверяется по действию, демо-стенд ничего не публикует для всех
Раньше любой сотрудник (`StaffUserDep`) мог всё: специалист выдавал документы,
демо-деканат «в один тап» публиковал события для всех и одобрял чужие возможности,
а вошедший публичным кодом `STAFF-001` видел общую очередь — с заявками демо-копий,
то есть с настоящими именами экспертов из MAX, их PDF и правом писать им в чат от
имени бота через «Требует уточнения». Документация при этом обещала проверку ролей.
*Решение* (`core/deps.py`):
- Роль проверяется по действию: очередь и статусы — `STAFF_CLERK`, `STAFF_HEAD`,
  `ADMIN`; «Готова» и выдача — только `STAFF_HEAD` и `ADMIN`; события — `ORGANIZER`
  и `ADMIN`; модерация — `MODERATOR` и `ADMIN`. «Выдана» через смену статуса закрыта:
  без PDF это неправда, выдача — только кнопкой «Выдать документ».
- На демо-стенде (`DEMO_MODE`) коды сотрудников опубликованы, а роль деканата
  включается в один тап — такая роль ничего не доказывает. Поэтому события и
  модерация отвечают 403 `DEMO_READ_ONLY`, а возможность от сотрудника уходит на
  модерацию, как студенческая.
- Очередь: демо-деканат видит только свою копию (как и было), остальные сотрудники —
  всё, кроме демо-копий. У вошедшего по коду в очереди только синтетические студенты.
- Комментарий сотрудника — не длиннее 500 символов: он уходит студенту в чат.
  Ссылки в возможностях и обложки событий — только `http(s)` (обложка — ещё путь
  на своём сервере): `javascript:` в ленту для всех не попадёт. Фронтенд
  (`openExternal`) тоже открывает только веб-ссылки.
- `route_json` шаблона (маршрут согласования по ролям) так и не читается кодом —
  маршрут один на все шаблоны, он в `ALLOWED_TRANSITIONS`. Это записано в
  расхождениях `docs/02-architecture.md`, а не выдаётся за работающее.
