# Продукт: модули, скоуп, сценарии

## Концепция

**Кампус — первокурснику: справка файлом в чат, ответы по регламентам, свои люди.**
Приложение внутри мессенджера MAX. Пять модулей на одном ядре,
где **AI-ассистент — не шестой пункт меню, а интерфейс ко всем остальным**.

Слоган привязан к треку («развитие навыков, навигация на старте карьеры,
безопасная среда»): справка файлом в чат — крючок и главный сценарий, ассистент
по регламентам и афиша — навигация на старте, «Люди» — безопасная среда
(только подтверждённые студенты, контакт — при взаимном отклике). Решение 062.

```
                       ┌─────────────────────────────┐
   Экран чата в апке ─▶│   AI-АССИСТЕНТ              │
                       │   RAG + tool calling        │
                       └──┬───┬───┬───┬──────────────┘
                          │   │   │   │  вызывает как инструменты
        ┌─────────────────┘   │   │   └─────────────────┐
        ▼                     ▼   ▼                     ▼
  ┌──────────┐        ┌──────────────┐          ┌──────────────┐
  │ ЗАЯВКИ   │        │  КАЛЕНДАРЬ   │          │ ВОЗМОЖНОСТИ  │
  │ справки  │        │  вуза        │          │ хакатоны     │
  │ стипендии│        │  события     │          │ конкурсы     │
  └──────────┘        └──────────────┘          └──────┬───────┘
                                                        │ «ищу команду»
  ┌──────────────────────────────────────────────┐      │
  │ МАТЧИНГ (интенты, свайпы, buddy)             │◀─────┘
  └──────────────────────────────────────────────┘
        ▲                                   ▲
        └───────────┬───────────────────────┘
        ┌───────────┴────────────────────────────────┐
        │ ЯДРО: initData-auth · binding · роли        │
        │ OUTBOX → push-уведомления в чат MAX         │
        └─────────────────────────────────────────────┘
```

**Две стыковки, делающие из набора фич систему** (подсветить на защите):

1. Возможность «хакатон» → кнопка «ищу команду» → создаёт интент в матчинге со ссылкой на хакатон
2. Ассистент отвечает про справки → отдаёт шаблон из модуля заявок → диплинк в форму

## Модуль 1. Заявки и справки

### Идея: движок шаблонов, а не набор форм

Шаблон заявки — запись в БД с JSON-описанием полей и маршрута.
**Новый тип справки = вставка строки, не релиз.** Главный аргумент на защите.

```json
{
  "key": "scholarship_social",
  "title": "Заявление на социальную стипендию",
  "icon": "💰",
  "sla_hours": 120,
  "fields": [
    { "name": "category", "type": "select", "label": "Основание",
      "options": ["Малоимущая семья", "Инвалидность", "Потеря кормильца", "Сирота"],
      "required": true },
    { "name": "doc_scan", "type": "file", "label": "Подтверждающий документ",
      "accept": ["image/*", "application/pdf"], "maxSizeMb": 10, "required": true },
    { "name": "comment", "type": "text", "label": "Комментарий", "maxLength": 500 }
  ],
  "route": [
    { "status": "IN_REVIEW", "actor_role": "STAFF_CLERK" },
    { "status": "SIGNING",   "actor_role": "STAFF_HEAD" },
    { "status": "READY" }
  ],
  "doc_template": "scholarship_decision"
}
```

Типы полей MVP: `text` · `textarea` · `number` · `select` · `multiselect` · `bool` · `date` · `file`

### Стартовый набор шаблонов (контент, не код)

справка об обучении · справка в военкомат · справка о стипендии/доходах ·
социальная стипендия · матпомощь · общежитие · академический отпуск · справка-вызов на сессию

### Машина состояний

```
DRAFT ─▶ SUBMITTED ─▶ IN_REVIEW ─▶ SIGNING ─▶ READY ─▶ ISSUED
                          │ ▲
                          ▼ │
                      NEEDS_INFO        ─▶ REJECTED
                                        ─▶ CANCELLED (студентом, до SIGNING)
```

`NEEDS_INFO` обязателен — реальный сценарий «донесите документ», показывает,
что процесс списан с жизни, а не выдуман.

**Типовые — автоматически, нетиповые — через сотрудника.** Шаблон с флагом
`auto_issue` (справка об обучении) выдаётся при подаче: те же шаги машины
состояний, PDF и файл в чат: типовой документ собирается из данных справочника
студентов, человеку в нём проверять нечего. Заполненное поле с `manual_review` (оригинал
с печатью, особая формулировка) возвращает заявку в очередь деканата.
В демо данные берутся из синтетического справочника, подписи нет (решение 059).

### Трекинг статуса как у доставки

Вертикальный степпер с таймстемпами и SLA. Главное «боль → лекарство»:
при переписке по почте студент отправил письмо и сидит в тишине неделю.

```
✅ Отправлена          23 сен, 14:02
✅ Принята в работу    23 сен, 16:41   — Петрова А.И.
🔵 На подписи          24 сен, 09:15   ← сейчас
⚪ Готова
⚪ Выдана
⏱ Обычно занимает 3 дня · осталось ~1 день
```

### Роль деканата — обязательна

Та же мини-апка, другой корень навигации. Очередь заявок с фильтрами,
кнопки `Принять` · `Запросить уточнение` · `Отклонить` · `Выдать`.

`Выдать` → генерится PDF → загружается в MAX → **студенту в чат падает файл**.

**Это вау-момент демо.** Два устройства рядом: слева студент подаёт, справа деканат выдаёт,
слева приходит PDF. Без роли деканата справки выглядят как форма в никуда.

### PDF и честность про ЭЦП

PDF с QR-кодом на `/verify/{uuid}` — публичная страница проверки подлинности
(кому выдан, когда, кем, срок, статус). На защите говорить прямо: юридическую силу
даёт ЭЦП, у нас её нет; показан механизм проверки, который с ЭЦП стыкуется в одну точку.
Вопрос «а это законно?» прилетит гарантированно.

## Модуль 2. Календарь вуза

Не расписание пар, а **события вуза**: собрания, старостаты, встречи с деканатом,
дни открытых дверей, дедлайны подачи документов, посвящение, конференции.

### Таргетинг аудитории — ключевая деталь

```jsonc
// audience_json
{ "faculties": ["ИМИТ"], "courses": [1], "groups": [], "only_freshmen": true }
```

Пустой массив = все. Лента = события, чья аудитория пересекается с профилем студента.
Без этого первокурснику ИМИТ прилетает собрание аспирантов юрфака и продукт выглядит сырым.

### Регистрация и места

Статусы: `REGISTERED` · `WAITLIST` · `CANCELLED` · `ATTENDED`

**Гонка за последнее место — реальный баг, который будет.** Занятие места только в транзакции
с `SELECT ... FOR UPDATE` по событию + частичный уникальный индекс на `(event_id, student_id)`.

При отмене — поднять первого из вейтлиста и сразу отправить push. Заметная приятная деталь.

### Напоминания

Джоб раз в 5 минут: события через 24 ч и через 1 ч → в outbox всем `REGISTERED`.
Дедуп по ключу `event_remind:{event_id}:{user_id}:24h`, иначе при рестарте воркера двойные пуши.

## Модуль 3. Возможности

Хакатоны, олимпиады, конкурсы, гранты, стажировки, волонтёрство —
внутри вуза и снаружи. Добавляют и сотрудники, и **студенты** (UGC).

`kind`: HACKATHON · CONTEST · OLYMPIAD · CONFERENCE · GRANT · INTERNSHIP · VOLUNTEER
`level`: INTERNAL · CITY · REGIONAL · FEDERAL · INTERNATIONAL

### UGC ⇒ модерация обязательна

Студенческие записи создаются в `PENDING`, в ленте видны только `APPROVED`.
Автор видит свою всегда, со статусом. Без модерации на защите спросят про спам и рекламу.

### Рекомендации — скоринг, не ML

```
score = 3 · пересечение тегов с профилем
      + 2 · уровень уместен курсу        (1 курс → INTERNAL/CITY выше)
      + 2 · дедлайн в окне 3–30 дней
      + 1 · совпал факультет
      + 1 · однокурсники уже отметили INTERESTED   ← соц. сигнал
      − 5 · дедлайн прошёл
```

Считается одним SQL-запросом, объясняется за 15 секунд, не падает на пустых данных.
Никакого ML — на хакатоне это ловушка времени.

### Стыковка с матчингом

`POST /api/opportunities/{id}/looking-for-team` → создаёт `intent(kind=TEAM, opportunity_id=id)`,
который попадает в колоду свайпов. Самая красивая связка в проекте, показать отдельным шагом демо.

## Модуль 4. AI-ассистент

**Живёт экраном внутри мини-апки**, не в чате мессенджера.

### Не просто RAG, а RAG + tool calling

Вопрос «где моя справка?» не решается поиском по регламентам — нужен вызов внутреннего API.

> ⚠️ **Изменено решением 019** (см. `05-llm-notes.md`): `search_regulations` **не тул**.
> RAG выполняется принудительно на каждый вопрос — фрагменты подмешиваются в системное
> сообщение до вызова модели. Причина: проверка показала, что YandexGPT не доводит
> цепочку инструментов до конца и теряет часть составного вопроса.

| Tool | Возвращает | Действие? |
|---|---|---|
| ~~`search_regulations(query, top_k)`~~ | принудительный pre-fetch, не тул | — |
| `list_request_templates()` | Какие справки бывают | нет |
| `get_my_requests(status?)` | Мои заявки, статусы, сроки | нет |
| `start_request(template_key)` | **Диплинк на экран формы**, не создание | нет |
| `list_calendar_events(from, to, kind?)` | События под аудиторию студента | нет |
| `register_for_event(event_id)` | Требует подтверждения пользователем | **да** |
| `list_opportunities(kind?, deadline_before?)` | Рекомендованные возможности | нет |
| `get_my_matches()` | Мои матчи и отклики | нет |
| `escalate_to_human(department, question)` | Создаёт тикет в деканат | **да** |

### Четыре нерушимых правила

1. **Авторизация в слое исполнения, не у модели.** `student_id` берётся из сессии (ContextVar),
   а не из аргументов тула. В схеме тула поля «чей» физически нет. Иначе дыра:
   «покажи заявки Иванова».
2. **Действия только с подтверждением.** `start_request` возвращает диплинк, а не создаёт заявку.
   Галлюцинация не должна уметь подать заявление на академ.
3. **Нет в базе знаний — «не знаю» + эскалация.** Выдуманный порядок начисления стипендии —
   худшее, что может случиться на демо.
4. **Каждый ответ про правила — с источником.** Возвращать `sources: [{title, url, snippet}]`.

### Наполнение базы знаний

**Начинать в первый день, параллельно с кодом.** 30–50 документов: порядок получения справок,
положение о стипендиях, контакты и часы приёма деканатов, FAQ первокурсника, правила общежития,
порядок перевода/восстановления, академический календарь.

Если оставить на конец — ассистент на демо будет отвечать «не знаю» на всё.

⚠️ Не смешивать демо-контур с официальным каталогом вуза: разные источники, разная актуальность,
склейка порождает ответы, которые выглядят авторитетно и при этом неверны.

## Модуль 5. Матчинг («тиндер для первашей»)

### Свайпаем интенты (объявления), а не людей

Карточка в колоде — конкретная потребность с тегами и сроком жизни.

```
🧪 Ищу напарника на лабу
БД, вариант 7, дедлайн 28.09
Могу объяснить SQL, туплю в нормализации
#БазыДанных #Лабы #Очно
Аня, 2 курс, ИМИТ
```

| Проблема классического «тиндера» | Как решается интентами |
|---|---|
| Холодный старт | Один человек = 3–5 карточек → колода вчетверо плотнее |
| Модерация / харассмент | Модерируется текст объявления, а не человек |
| Пустой матч | Есть понятный повод написать, а не «привет» в пустоту |
| «Это же про знакомства» | Продукт про учёбу и адаптацию — снимает главное возражение жюри |

Виды интентов: `STUDY_BUDDY` · `MENTOR` · `MENTEE` · `COMMUTE` · `TEAM` · `HOBBY`

### Buddy-автоматч — страховка от пустой колоды

Поток **без свайпов вообще**: первокурсник отмечает «хочу наставника» → джоб подбирает
старшекурсника того же направления с незаполненной квотой → обоим push с карточкой и кнопкой.

Матч гарантирован даже когда в базе три человека. На демо всегда есть что показать.
Самая сильная часть истории про адаптацию.

### Скоринг колоды

```
3·теги + 2·факультет + 1·близкий курс + 1·район (для COMMUTE) − 2·возраст интента
```

## Приоритеты при нехватке времени

1. **Ядро** (auth, binding, роли, outbox) — без него ничего не работает
2. **Заявки end-to-end** — доводить до PDF в чате, прежде чем начинать следующее
3. **Ассистент** — сначала голый RAG, потом тулы по одному, начиная с `get_my_requests`
4. Календарь + возможности (похожи, делаются вместе)
5. Матчинг

Заявки + ассистент — связка, которая сама по себе выглядит законченным продуктом.
Резать при нехватке времени следует с конца списка.

## Сценарий демо (3 минуты)

1. Первокурсник открывает апку из чата → привязка по коду (10 сек)
2. Спрашивает ассистента словами: «нужна справка для стипендии» → ответ с источником + кнопка
3. Заполняет форму в три поля → отправил
4. **Второе устройство:** у деканата всплыла заявка → Принял → Подписал → «Выдать»
5. **Первое устройство:** в чате лежит PDF. Открыли, показали QR → страница проверки
6. «А ещё я тут никого не знаю» → колода → отклик на «ищу напарника на лабу» → взаимно → push обоим
7. Финал: «семь типов справок уже работают — это JSON-файлы, не код»

Записать видео заранее как страховку от падения сети на площадке.
