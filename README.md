# Кампус — мини-приложение для мессенджера MAX

**Кампус — первокурснику: справка файлом в чат, ответы по регламентам, свои люди.**

Справки и заявления без визита в деканат — готовый PDF приходит прямо в чат MAX.
Ассистент отвечает по регламентам вуза. Афиша событий, конкурсов и хакатонов —
навигация на старте учёбы и карьеры, а «Люди» — безопасная среда для знакомств:
только подтверждённые студенты вуза, контакт открывается при взаимном отклике.

**Хакатон по разработке чат-ботов и мини-приложений для MAX.**
Направление — образовательные решения. Бот: **@t355_hakaton_max_bot**

> **Тезис продукта.** Это не сайт в обёртке мессенджера. Это двусторонний канал:
> заявка уходит из приложения, а готовая справка возвращается **файлом прямо в чат**.
> Почта заменяется не формой, а замкнутым циклом с видимым статусом.

## Как запустить

```bash
git clone <репозиторий> && cd max-campus
cp .env.example .env          # заполнить MAX_BOT_TOKEN, YC_API_KEY, YC_FOLDER_ID
bash scripts/fetch_certs.sh   # корневые сертификаты Минцифры для TLS до MAX API

docker compose up -d --build              # локально на http://localhost:8000
docker compose --profile tunnel up -d     # плюс публичный HTTPS через cloudflared
docker compose logs tunnel | grep trycloudflare   # адрес появится здесь
```

База наполняется сама при первом старте: шаблоны заявок, база знаний,
студенты, события, конкурсы и объявления. Отдельных миграций запускать не нужно.

**Проверка, что всё поднялось:**

```bash
curl http://localhost:8000/api/health
python scripts/smoke_test.py               # сквозной сценарий, безопасность и демо-вход, 68 проверок
python scripts/test_assistant.py           # качество ответов ассистента
docker compose exec -T app python - < scripts/test_bot_buttons.py   # кнопки бота, без сети
```

### Подключение бота

```bash
python scripts/setup_bot.py                         # имя бота и текущие подписки
python scripts/setup_bot.py subscribe https://<адрес>/webhook/max
```

Ссылку на мини-приложение отправить организаторам через
[форму сбора ссылок](https://sbor-ssylok-dlya-mini-prilojeniy.testograf.ru/) —
привязку к боту выполняют они, регистрация в «MAX для партнёров» не нужна.

## Демонстрационный сценарий

Основной путь, который проходят эксперты. Кодов не нужно: каждый аккаунт получает
свою копию синтетического студента, а роль деканата включается в один тап — второе
окно не нужно, и эксперты не мешают друг другу. В браузере вне MAX каждому браузеру
выдаётся свой тестовый пользователь.

| Шаг | Что сделать | Что увидеть |
|---|---|---|
| 1 | Открыть приложение → **«Попробовать как студент (демо)»** | Свой демо-профиль: ваше имя из MAX, Б-25-1, 1 курс ИМИТ, зачётка `DEMO-…` |
| 2 | Вкладка **Чат** → «Сколько дней делается справка об обучении?» | Ответ по регламенту со ссылкой на источник |
| 3 | Там же → «Какие справки я могу заказать?» | Список из базы + кнопка перехода к форме |
| 4 | **Заявки → Новая → Справка об обучении** | Форма собрана из JSON-шаблона, не свёрстана руками; пометка «сразу» — справка типовая |
| 5 | Выбрать, куда нужна справка → **«Получить PDF сразу»** | Степпер за пару секунд проходит все шаги: справка выдана автоматически, PDF — в заявке и файлом в чате с ботом |
| 6 | Новая заявка: включить «Нужен оригинал» (или другой вид справки) → отправить | Нетиповая заявка — «Отправлена», ждёт сотрудника, срок в днях |
| 7 | Профиль → **«Включить роль деканата (демо)»** | Появилась вкладка **Деканат**, в очереди — только ваши заявки |
| 8 | Деканат → заявка → Принять → На подпись → **Выдать документ** | PDF сформирован |
| 9 | Вернуться студентом на экран заявки | Документ, кнопка «Открыть PDF» |
| 10 | Открыть QR-ссылку из PDF | Страница проверки подлинности |
| 11 | **Люди** → полистать колоду, откликнуться | Совпадение → контакт в «Откликах» |

Сброс между показами: `bash scripts/reset_demo.sh` — коды привязки снова свободны,
демо-копии удалены.

**Коды для проверки** — второй путь, так входил бы настоящий студент по коду из деканата

| Назначение | Код |
|---|---|
| Студент (основной сценарий) | `A7K2-9M` |
| Студенты (запасные) | `B3N8-4P`, `C5R1-7T`, `D9W6-2L` |
| Специалист деканата | `STAFF-001` |
| Заместитель директора (может выдавать) | `STAFF-002` |

## Что внутри

### Заявки и справки — движок, а не набор форм

Тип справки описывается JSON-шаблоном: поля, правила валидации, маршрут
согласования, шаблон документа. Бэкенд по нему проверяет данные, фронтенд —
рисует форму. **Новый вид справки добавляется строкой в таблицу, без единой
правки кода.** Сейчас настроено девять: справка об обучении, в военкомат,
о стипендии, социальная стипендия, материальная помощь, общежитие,
академический отпуск, справка-вызов, обращение в деканат.

Машина состояний с проверкой допустимых переходов и ролей:

```
SUBMITTED → IN_REVIEW → SIGNING → READY → ISSUED
                ↕
           NEEDS_INFO              → REJECTED / CANCELLED
```

Каждый переход пишется в историю и порождает сообщение студенту в чат.
Состояние `NEEDS_INFO` — не украшение: это реальный сценарий «донесите документ»,
и студент отвечает на него прямо из приложения.

**Типовые справки выдаются сразу.** Флаг `auto_issue` в шаблоне: справку
об обучении тот же запрос, что её подал, проводит по тем же шагам машины
состояний, формирует PDF и ставит в очередь сообщения в чат — «заявка принята»
и файл. Выдающий в истории и в PDF — «Демо-деканат (автоматическая выдача)».
Поле с флагом `manual_review` (бумажный оригинал с печатью, особая формулировка)
делает заявку нетиповой — она идёт в очередь сотрудника, как и остальные виды.
Если PDF сформировать не удалось, заявка тоже остаётся сотруднику, а не падает
с ошибкой. Код — `modules/requests/service.py`, решение 059.

### Ассистент — RAG с принудительным заземлением

Устроен не как «поиск по документам», а как рабочий инструмент, которому нельзя
соврать. Четыре механизма, каждый появился после конкретного наблюдаемого сбоя:

1. **Поиск по регламентам выполняется всегда**, до обращения к модели.
   Гибридный: векторный (pgvector) плюс полнотекстовый русский, объединение
   через RRF. Модель не может «забыть» посмотреть документ.
2. **Данные подтягиваются заранее по формулировке вопроса.** На «какие идут
   хакатоны» модель однажды не вызвала инструмент и выдумала три несуществующих
   мероприятия. Теперь факты уже лежат в контексте — выдумывать нечего.
3. **Ответ проверяется после генерации.** Служебные строки вырезаются;
   если инструменты дали данные, а модель всё равно ответила «не знаю»,
   делается ещё один проход с данными в открытом виде.
4. **Ответ не зависает.** Весь ответ укладывается в 25 секунд. Если модель
   не успела или упала, приходит не ошибка, а одна-две выдержки из найденных
   регламентов с пометкой «Модель не ответила — вот что сказано в регламенте».
   На вопрос про свою заявку — не выдержка, а кнопки к заявкам.
   На экране вместо трёх точек — этапы («Ищу в регламентах… → Сверяю с твоими
   данными… → Формулирую ответ…»), через 20 секунд — кнопка «Повторить».
   Повтор не начинает заново, а дожидается того же ответа: второй раз модель
   не спрашивается и вопрос в истории не дублируется.

Инструменты исполняются от имени текущего пользователя — параметра «чей»
в их схеме нет, поэтому «покажи заявки Иванова» не работает by design.
Заявки ассистент не создаёт: он возвращает кнопку, форму заполняет человек.
Исключение — обращение в деканат (крайняя мера, когда ответа нет ни в данных,
ни в регламентах): оно записывается сразу, отдельно от ответа, и не теряется,
даже если модель не договорила.

### Календарь вуза

События с таргетингом по факультету, курсу и группе — первокурсник ИМИТ
не видит собрание аспирантов юрфака. Запись с ограничением мест,
лист ожидания и автоматическое поднятие первого в очереди при освобождении места.
Занятие места идёт в транзакции с блокировкой строки: иначе два одновременных
запроса заняли бы один слот.

### Возможности

Хакатоны, конкурсы, олимпиады, стажировки, гранты. Ранжируются взвешенным
скорингом: совпадение интересов, уместность уровня курсу, близость дедлайна,
сколько однокурсников уже отметились. Никакого машинного обучения — правило
объясняется за пятнадцать секунд и не ломается на пустых данных.

Студенты могут предлагать свои — такие публикации уходят на модерацию.
У каждой возможности есть кнопка «ищу команду»: она создаёт объявление
в разделе знакомств. Так два модуля связываются в один сценарий.

### Знакомства для первокурсников

Свайпаются **объявления, а не люди**. Это решает сразу три проблемы: холодный
старт (один человек создаёт несколько карточек), модерацию (проверяется текст,
а не человек) и пустой матч (есть понятный повод написать).

Плюс поток без свайпов вообще: первокурсник отмечает «хочу наставника»,
и система сама подбирает старшекурсника того же направления. Матч гарантирован,
даже когда в базе три человека.

## Архитектура

```
        MAX-клиент
   ┌──────────┴───────────┐
   │                      │
 Бот                Мини-приложение
 (вход, пуши,       (React + TypeScript)
  доставка PDF)             │
   │                        │ initData в заголовке
   └────────┬───────────────┘
            ▼
    FastAPI (Python)
      ├ проверка подписи запуска
      ├ привязка аккаунта MAX ↔ студент
      ├ движок заявок и машина состояний
      ├ генерация PDF + страница проверки
      ├ ассистент: RAG + вызов инструментов
      ├ календарь, возможности, знакомства
      └ очередь исходящих сообщений
            ▼
   PostgreSQL + pgvector · файлы на диске
```

**Решения, которые стоит отметить:**

- **Один сервис отдаёт и API, и фронтенд.** Одно происхождение, один HTTPS-адрес,
  никакого CORS — для мини-приложения это заметно проще в эксплуатации.
- **Очередь живёт в Postgres**, фоновые задачи — обычные asyncio-циклы.
  Redis и внешний планировщик не заводились сознательно: меньше сервисов,
  меньше мест, где что-то не поднимется на демонстрации.
- **Все исходящие сообщения идут через таблицу `outbox`** с дедупликацией,
  ретраями и ограничителем скорости. Прямых вызовов Bot API из обработчиков нет.
- **Тихие часы**: напоминания не уходят ночью, переносятся на утро.

## Что смоделировано

Требование FAQ (пп. 13, 15) — явно обозначить, что реализовано моделью.

| Область | Состояние | Что нужно для продуктива |
|---|---|---|
| Справочник студентов | **Смоделирован**: 12 синтетических записей | Выгрузка из деканата или интеграция с учебной системой |
| Тексты регламентов | **Смоделированы**: 15 документов по типовым нормам вузов | Замена содержимого таблицы `kb_document` официальными актами |
| События и конкурсы | **Смоделированы** | Ручной ввод организаторами или импорт ICS/RSS |
| Роли сотрудников | Активируются кодом | Роль из кадровой системы |
| Электронная подпись документов | **Не применяется** | Интеграция с УКЭП; место стыковки — страница проверки |
| Автовыдача типовой справки | **Смоделирована**: данные — из синтетического справочника студентов, выдаёт «Демо-деканат (автоматическая выдача)», подписи нет, 1С не подключена | Данные контингента из 1С или учебной системы вуза, УКЭП для автоматически выдаваемых документов |
| Bot API, LLM, эмбеддинги | **Настоящие**, работают вживую | — |

PDF-документы **не имеют юридической силы**: усиленная квалифицированная
электронная подпись не применялась. Страница `/verify/{uuid}` подтверждает только
факт выдачи через сервис и текущий статус документа — это честно написано
и в самом документе, и на странице проверки.

## Разработка

```bash
# Бэкенд отдельно (нужна поднятая база: docker compose up -d db)
cd backend && python -m venv .venv
./.venv/Scripts/python -m pip install -e .
PYTHONPATH=. uvicorn app.main:app --reload

# Фронтенд отдельно, с проксированием API на бэкенд
cd frontend && npm install && npm run dev

# Типы API для фронтенда из живой схемы
cd frontend && npm run api:types
```

Вне мессенджера объект `window.WebApp` отсутствует, и приложение переходит
в режим разработки: вместо подписи отправляется `dev:<id>:<Name>`. Сервер
принимает такой вход только для тестовых id 900000–999999 (`TEST_USER_ID_MIN/MAX`
в `core/config.py`), остальные получают 401. Переключение тестового пользователя —
в профиле. Совсем выключается режим переменной `ALLOW_DEV_AUTH=false`.
Если приложение открыто кнопкой-ссылкой из бота (`?lt=…`), вместо dev-входа идёт
подписанный вход настоящего пользователя MAX — заголовок `Authorization: MaxLink <токен>`,
метка в углу — «Браузер · вход через бота».

### Особенности окружения

- **Кириллица в теле запроса из bash на Windows повреждается.** При ручной
  отладке API payload передавать файлом: `curl --data-binary @file.json`.
  Кода это не касается — Python-клиенты кодируют корректно.
- **Порт 5432 может быть занят** локально установленным PostgreSQL, поэтому
  контейнер поднимается на 5433.
- **TLS до `platform-api2.max.ru`** не работает без корневых сертификатов
  Минцифры: `bash scripts/fetch_certs.sh`.

## Безопасность

- Подпись запуска проверяется на сервере, сравнение constant-time, срок жизни — час
  (рекомендация MAX Bridge). Протухшая подпись — экран «Сессия устарела», а не сырая ошибка.
- Вход без подписи (режим разработки) — только для тестовых id 900000–999999:
  представиться настоящим пользователем MAX нельзя.
- Пока мини-приложение не привязано к боту, кнопка в чате — ссылка в браузер
  с подписанным входом `?lt=<id>.<срок>.<HMAC>` (сутки, секрет `LINK_SECRET` или
  производный от токена бота). Сервер проверяет подпись constant-time и срок,
  фронтенд сразу убирает токен из адресной строки, журнал доступа его вырезает.
  В карточки для пересылки (поделиться событием) токен не кладётся.
  Подделанная и просроченная ссылки — 401, это проверяет `smoke_test.py`.
- Вебхук бота с неверным `X-Max-Bot-Api-Secret` отклоняется (403); без заголовка —
  по флагу `MAX_WEBHOOK_REQUIRE_SECRET`.
- Фронтенд отдаётся только из папки сборки: обход вида `/..%2F..%2Fetc%2Fpasswd`
  получает `index.html`. Это и два пункта выше проверяет `smoke_test.py`.
- Роль сотрудника читается из справочника, а не из запроса.
- Подбор кода привязки ограничен: 5 попыток в час.
- Инструменты ассистента не принимают идентификатор пользователя параметром.
